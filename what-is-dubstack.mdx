dubstack is a documentation platform for technical products.

It combines a Git-backed docs source, a dashboard editor, generated API references, production docs hosting, and AI surfaces that can read and act on your documentation workflow.

## What dubstack helps you ship

Use dubstack when you need to publish and maintain:

- developer documentation
- API references from OpenAPI specs
- product guides and changelogs
- internal or partner-facing knowledge bases
- AI-readable docs through search, markdown export, and public MCP

## Core surfaces

| Surface | Purpose |
| --- | --- |
| Dashboard | Manage sites, source control, billing, team access, analytics, and deployment settings. |
| Editor | Edit MDX pages, navigation, assets, and site configuration from the browser. |
| Docs shell | Render your published documentation site from Git-backed content and `dubstack.json`. |
| API reference | Generate endpoint docs and interactive request builders from OpenAPI specs. |
| Assistant | Answer reader questions from published docs with linked sources. |
| Agent | Help maintain docs from dashboard and integration workflows. |
| Public MCP | Let AI tools search and read published docs through a read-only MCP server. |
| Theme Studio | Customize advanced docs experiences on Enterprise plans. |

## Source of truth

The docs source lives in Git.

`dubstack.json` controls the site structure, theme, API reference setup, widgets, redirects, and other site behavior. MDX files hold the actual content.

When content changes, dubstack syncs the source into the publish pipeline and serves the rendered site from the latest published content.

## Editing content

There are two supported editing paths, and teams can use both.

- Use the dashboard editor to edit and publish pages in the browser. Dashboard publishing writes changes back to the connected source when the source allows editor writes.
- Use a local editor and Git when developers want to clone the repository, edit MDX or `dubstack.json`, commit, push, and review changes through the Git provider.

Anyone who can write to the connected repository can update documentation through the repository workflow. Dashboard permissions and Git provider permissions are managed separately.

## How teams use it

Common workflows include:

- connect a GitHub, GitLab, or Forgejo repository
- start with a hosted starter repository
- edit pages and navigation from the dashboard
- clone the repository and push docs changes from a local editor
- publish preview deployments for branches
- generate API endpoint pages from OpenAPI specs
- attach a custom domain
- enable reader feedback, analytics, assistant, and MCP
