Credits measure AI work performed by dubstack surfaces such as assistant answers, agent actions, and workflow runs.

The exact credit cost depends on the action, the amount of context required, and the model profile used by the workspace.

## Where credits are used

| Surface | Examples |
| --- | --- |
| Assistant | Answering reader questions from published docs. |
| Agent | Drafting docs updates, creating pull requests, and using connected context. |
| Workflows | Running scheduled docs improvements and maintenance workflows. |
| Retrieval | Searching, ranking, and summarizing docs context for AI responses. |

Repository sync and one-time repository copy actions are not counted as AI credits when they only move files between Git providers or published artifacts. Scheduled repository-copy workflows are workflow runs, so they consume automation credits and appear in workflow usage. Repository-copy workflow credits start at 35+ credits per run. Before execution, the workflow reserves credits from the active source file count and configured target count, then finalizes usage from the actual copy result.

## Plan limits

Plan limits are shown on the billing page and in the subscription reference. Pro workspaces include a default monthly AI credit allowance, and Enterprise workspaces can use a custom allowance configured for the account.

The default Pro allowance is 10,000 credits per month. The dashboard remains the source of truth for the current workspace allowance, billing window, used credits, remaining credits, and whether quota enforcement is passive or enforced.

Free workspaces do not include permanent AI credits. During a Pro trial, the workspace can use the Pro allowance for the trial window. When the trial ends, ongoing AI usage requires Pro, Enterprise, or another explicit entitlement.

Additional credit packages can be purchased from billing or usage settings when they are enabled for the workspace. Overage is separate and must be turned on deliberately before usage can continue past an enforced allowance.

## Credit packages

Credit packages are workspace-level. They are shared across assistant, agent, Slack, and workflow usage.

| Monthly credits | Monthly cost |
| --- | --- |
| 10,000 included credits | Included with Pro or an active Pro trial |
| 25,000 credits | USD 120/month |
| 50,000 credits | USD 300/month |
| 100,000 credits | USD 650/month |

The dashboard is the source of truth for the packages currently available to your workspace. Enterprise workspaces can have custom allowances or commercial terms.

Crossing your allowance does not automatically move you to a larger package. If overage is disabled, eligible AI requests can be blocked or held when quota enforcement is active. If overage is enabled, extra usage can continue and is reported separately from the included allowance.

Default overage is USD 0.008 per credit when enabled. Overage is off by default.

Unused credits do not roll over by default. Rollover only applies when it is explicitly enabled for the workspace.

## Good practices

- Use the assistant for reader-facing answers.
- Use the agent for authoring, workflow, and pull request tasks.
- Keep docs content structured so retrieval needs less context to answer accurately.
- Review analytics and feedback to decide where workflow is worth spending credits.
- Schedule broad maintenance workflows deliberately instead of triggering them on every content or code change.
- Keep workflow context narrow with repository, branch, path, integration, and prompt scope.
- Treat manual and API-triggered workflow runs like scheduled runs for credit planning.

## Workflow credit planning

Workflow runs can vary more than assistant answers because they may read multiple files, inspect repository context, query integrations, draft changes, and prepare review requests.

Manual runs, scheduled runs, and Admin API-triggered runs all use the saved workflow configuration and appear in workflow history. If the run uses a workflow runner, it can record estimated or charged credits according to the workspace billing mode.

Use scheduled workflows when you want predictable monthly usage. For example, a weekly SEO audit or broken-link check is easier to forecast than running the same workflow on every content update.

Use event-based workflows when timeliness matters more than predictable credit volume, such as updating docs from merged source-code changes.

Use repository-copy workflows for scheduled portability checks, backups, or migration rehearsal. They start at 35+ credits per run and scale with target count and file volume because they perform provider reads, provider writes, validation, and audit logging. Quota checks happen before the copy starts, using a preflight source-file and target-count estimate.
