Language routing lets one docs site serve translated pages from locale-prefixed paths.

Use it when you maintain translated MDX files in the same docs repository and want readers to switch between language versions from the docs shell.

## File structure

Keep the default language at the root of the docs repo. Put translated pages in language-code directories.

```text
index.mdx
quickstart.mdx
fr/
  index.mdx
  quickstart.mdx
es/
  index.mdx
  quickstart.mdx
zh/
  index.mdx
  quickstart.mdx
```

DubStack detects translated pages from two-letter locale prefixes such as `fr`, `es`, and `zh`.

## Configure the selector

Add `navigation.languages` to `dubstack.json`.

```json
{
  "navigation": {
    "languages": [
      {
        "code": "en",
        "label": "English",
        "href": "/"
      },
      {
        "code": "fr",
        "label": "Français",
        "href": "/fr"
      },
      {
        "code": "es",
        "label": "Español",
        "href": "/es"
      }
    ],
    "tabs": [
      {
        "tab": "Guides",
        "default": true,
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      }
    ]
  }
}
```

The selector appears when at least one language is configured.

## Page matching

When a reader switches languages, DubStack keeps the same page path when the translated file exists.

For example:

| Current page | French target |
| --- | --- |
| `/quickstart` | `/fr/quickstart` |
| `/configuration/navigation` | `/fr/configuration/navigation` |

If the translated page is missing, the reader stays on the closest available language home or falls back to the default page.

## Language-specific banners

Each language can define its own banner.

```json
{
  "navigation": {
    "languages": [
      {
        "code": "en",
        "label": "English",
        "href": "/",
        "banner": {
          "content": "New docs launch: review the migration guide.",
          "dismissible": true
        }
      },
      {
        "code": "fr",
        "label": "Français",
        "href": "/fr",
        "banner": {
          "content": "Nouveaux documents: consultez le guide de migration.",
          "dismissible": true
        }
      }
    ]
  }
}
```

If a language does not define a banner, the site-level [banner](/configuration/banners) is used when configured.

## Properties

<ResponseField name="code" type="string" required>
  Language code used in URLs and page matching. Use a two-letter code such as `en`, `fr`, `es`, or `zh`.
</ResponseField>

<ResponseField name="label" type="string">
  Human-readable label shown in the language selector. If omitted, DubStack derives a label from the language code.
</ResponseField>

<ResponseField name="flag" type="string">
  Optional flag or icon label shown beside the language. If omitted, DubStack uses the default flag for known language codes.
</ResponseField>

<ResponseField name="href" type="string">
  Optional language home path. If omitted, English uses `/` and other languages use `/{code}`.
</ResponseField>

<ResponseField name="banner" type="object">
  Optional language-specific banner configuration. It uses the same shape as the top-level `banner` field.
</ResponseField>

## Translation workflow boundary

Language routing does not automatically translate content.

Keep translated files in source control and publish them like any other MDX file. Translation workflows can help draft or maintain translated content when they are enabled for the deployment, but the published site only serves files that exist in the docs repository.

## Checklist

- Keep filenames and folder structure consistent across languages.
- Use one language code per translated directory.
- Add only languages that have enough translated content to be useful.
- Review links inside translated pages so they point to translated paths where available.
- Publish after changing `navigation.languages` so search and public MCP reflect the current language structure.
