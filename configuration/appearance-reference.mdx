Use these fields to control the visual identity of a DubStack docs site from source.

Prefer the dashboard Site configuration editor for visual changes when your team wants a preview before publishing. Commit the same values to `dubstack.json` when your site is Git-reviewed.

## Theme shell and palette

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `theme` | string | Site default | Selects the layout shell, spacing rhythm, sidebar/header treatment, and API reference layout. |
| `palette` | string | Site default | Selects the color-token preset layered onto the theme shell. |
| `themeToggle` | boolean | `true` | Shows or hides the light/dark mode control. |

```json
{
  "theme": "prism",
  "palette": "classic",
  "themeToggle": true
}
```

`theme` and `palette` are separate on purpose. Use the shell that gives the right layout, then apply the palette and brand colors that match your product.

## Brand colors

| Field | Type | Purpose |
| --- | --- | --- |
| `colors.primary` | string | Primary brand/accent color. Used for active states, links, and key controls. |
| `colors.light` | string | Brand token used where the renderer needs a brighter accent, usually in dark contexts. |
| `colors.dark` | string | Brand token used where the renderer needs a darker accent, usually in light contexts. |
| `theme.colors.background` | string | Advanced background token for the selected shell. |
| `theme.colors.foreground` | string | Advanced foreground text token. |
| `theme.colors.muted` | string | Advanced muted text token. |
| `theme.colors.border_default` | string | Advanced default border token. |
| `theme.colors.border_subtle` | string | Advanced subtle border token. |

```json
{
  "colors": {
    "primary": "#15803D",
    "light": "#07C983",
    "dark": "#15803D"
  }
}
```

Use `colors.*` for normal brand overrides. Use `theme.colors.*` only when you need lower-level token control across the docs shell.

## Logo and favicon

| Field | Type | Purpose |
| --- | --- | --- |
| `site.name` | string | Public site name used by the header, browser metadata, AI discovery, and MCP labels. |
| `site.tagline` | string | Short site description used in metadata and discovery surfaces. |
| `site.logo.light` | string | Logo shown in light mode. |
| `site.logo.dark` | string | Logo shown in dark mode. |
| `site.favicon` | string or object | Browser favicon. Use one path or light/dark paths when contrast differs. |
| `site_header.logo_url` | string | Advanced header logo override. Usually managed by the dashboard. |
| `site_header.show_logo` | boolean | Shows or hides the header logo. |
| `site_header.show_brand` | boolean | Shows or hides the site name next to the logo. |

```json
{
  "site": {
    "name": "Acme Docs",
    "tagline": "Developer documentation for Acme.",
    "logo": {
      "light": "/logo/light.svg",
      "dark": "/logo/dark.svg"
    },
    "favicon": {
      "light": "/assets/favicon-light.svg",
      "dark": "/assets/favicon-dark.svg"
    }
  }
}
```

Asset paths are resolved from the published docs repository. Keep the files in source so previews, production, and branch deployments use the same assets.

## Fonts

| Field | Type | Purpose |
| --- | --- | --- |
| `fonts.heading` | string | Heading font family. |
| `fonts.body` | string | Body text font family. |
| `fonts.code` | string | Code and inline-code font family. |

```json
{
  "fonts": {
    "heading": "Inter",
    "body": "Inter",
    "code": "JetBrains Mono"
  }
}
```

Use fonts available in the dashboard selector unless your deployment has a custom font-loading plan.

For examples, supported family names, and fallback guidance, see [Fonts](/configuration/fonts).

## Code blocks and inline code

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `styling.codeblocks` | string | `system` | Code block theme mode. Use `system` unless you need a fixed theme. |
| `theme_config.code_block.syntax_theme` | string | Theme default | Advanced syntax theme override. |
| `theme_config.code_block.background` | string | Theme default | Advanced code block content background. |
| `theme_config.code_block.surface` | string | Theme default | Advanced code block surface background. |
| `theme_config.code_block.header_background` | string | Theme default | Advanced code block header background. |
| `theme_config.code_block.border_color` | string | Theme default | Advanced code block border color. |
| `theme_config.code_block.comment_color` | string | Theme default | Advanced comment/token accent color. |
| `theme_config.code_block.radius` | number | Theme default | Advanced code block border radius. |
| `theme_config.code_block.content_radius` | number | Theme default | Advanced code block content radius. |

```json
{
  "theme": "prism",
  "styling": {
    "codeblocks": "system"
  },
  "theme_config": {
    "code_block": {
      "syntax_theme": "github-dark",
      "background": "#0d0d0d",
      "header_background": "#18171A",
      "border_color": "#2d2d2d"
    }
  }
}
```

Advanced code block fields are useful for theme authors. Most sites should keep `styling.codeblocks` on `system` so light and dark mode stay coherent.

## Assistant appearance

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `widgets.assistant.title` | string | `Assistant` | Label shown in the assistant header. |
| `widgets.assistant.welcome_title` | string | Site-aware default | Empty-state heading before the reader asks a question. |
| `widgets.assistant.welcome_subtitle` | string | Theme default | Empty-state helper text. |
| `widgets.assistant.user_bubble_color` | string | Theme token | Background for reader messages. |
| `widgets.assistant.user_bubble_text_color` | string | Theme token | Text color for reader messages. |
| `widgets.assistant.ai_bubble_color` | string | Theme token | Assistant message background for layouts that render assistant bubbles. Docs-shell answers can stay unboxed. |
| `widgets.assistant.ai_bubble_text_color` | string | Theme token | Assistant answer text color. |
| `widgets.assistant.source_card_background_color` | string | Theme token | Background for assistant source cards. |
| `widgets.assistant.source_card_border_color` | string | Theme token | Border for assistant source cards. |
| `widgets.assistant.source_card_text_color` | string | Theme token | Source title text color. |
| `widgets.assistant.source_card_muted_color` | string | Theme token | Source path and snippet text color. |

```json
{
  "widgets": {
    "assistant": {
      "title": "Assistant",
      "welcome_title": "How can I help with Acme?",
      "welcome_subtitle": "Ask about setup, publishing, and API workflows.",
      "user_bubble_color": "color-mix(in srgb, var(--assistant-bg) 86%, var(--foreground) 14%)",
      "user_bubble_text_color": "var(--assistant-text)",
      "source_card_background_color": "color-mix(in srgb, var(--assistant-bg) 94%, var(--foreground) 6%)",
      "source_card_border_color": "color-mix(in srgb, var(--assistant-border) 70%, transparent)",
      "source_card_text_color": "var(--assistant-text)",
      "source_card_muted_color": "var(--docs-muted-text, var(--gray-400))"
    }
  }
}
```

Prefer theme variables or `color-mix(...)` values when the same configuration should adapt across light and dark mode.

## Custom CSS

| Field | Type | Purpose |
| --- | --- | --- |
| `custom_css` | string | Inline custom CSS for advanced docs-shell overrides. Enterprise feature. |

```json
{
  "custom_css": "#content-area { max-width: 980px; }"
}
```

Use custom CSS sparingly. Prefer source-backed theme settings first so previews, generated screenshots, and AI-readable pages remain predictable.

See [Custom CSS](/configuration/custom-css) for stable hooks, review guidance, and boundaries.
