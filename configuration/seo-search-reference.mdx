Use these settings to control discoverability for humans, search engines, and AI agents.

## Site metadata

| Field | Type | Purpose |
| --- | --- | --- |
| `site.name` | string | Site title used in metadata, UI labels, AI discovery, and MCP labels. |
| `site.tagline` | string | Short site description used in metadata and discovery surfaces. |

```json
{
  "site": {
    "name": "Acme Docs",
    "tagline": "Developer documentation for Acme."
  }
}
```

Use page frontmatter for page-specific titles and descriptions. Use global site metadata for defaults.

## Page frontmatter

| Field | Type | Purpose |
| --- | --- | --- |
| `title` | string | Page title and navigation fallback. |
| `description` | string | Page summary used by metadata, search snippets, and AI-readable indexes. |
| `icon` | string | Page icon when supported by navigation. |
| `noindex` | boolean | Excludes the page from public indexing surfaces. |
| `searchable` | boolean | Set to `false` to exclude a published page from in-site search, public MCP search, the public MCP filesystem, and assistant retrieval indexes without removing the page from navigation. |
| `boost` | number | Positive relevance multiplier for search and assistant retrieval ranking. |

```mdx
---
title: Quickstart
description: Create and publish your first docs site.
icon: zap
boost: 2
---
```

Write descriptions as reader-facing summaries. They are reused by search, AI discovery, and previews.

## Indexing policy

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `addons.visibility.noindex` | boolean | `false` | Site-level switch to disable public indexing and AI discovery. |
| Page `noindex` frontmatter | boolean | `false` | Page-level switch to exclude a page from sitemap and public AI surfaces. |
| Page `hidden` frontmatter | boolean | `false` | Removes a page from navigation and public sitemap output. |
| Page `searchable` frontmatter | boolean | `true` | Set to `false` to keep the page published but remove it from search and public MCP retrieval. |

```json
{
  "addons": {
    "visibility": {
      "noindex": false
    }
  }
}
```

Published indexing is based on public navigation. Pages marked `hidden` or `noindex` are excluded from public sitemap output and public AI-readable surfaces. Pages marked `searchable: false` stay navigable and directly reachable, but are omitted from in-site search, public MCP search, the public MCP filesystem, and assistant retrieval indexes.

## Search controls

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `widgets.search.placeholder` | string | Theme default | Placeholder text in the search box. |
| Page `boost` frontmatter | number | `1` | Raises the ranking weight for that page in search and assistant retrieval. |
| Page `searchable` frontmatter | boolean | `true` | Removes a page from search and retrieval when set to `false`. |

```json
{
  "widgets": {
    "search": {
      "placeholder": "Search docs..."
    }
  }
}
```

Search results are built from published content. If a page is missing from search, check navigation, frontmatter, and indexing policy first.

```mdx
---
title: Quickstart
description: Create and publish your first docs site.
boost: 2
---
```

Use boosts for canonical pages that should win broad queries, such as quickstarts, migration guides, and primary API overview pages. Keep boosts modest so specific pages can still rank for specific queries.

```mdx
---
title: Terms of service
description: Legal terms linked from the footer.
searchable: false
---
```

Use `searchable: false` for utility pages that should remain public but should not appear in search or public AI retrieval.

## AI discovery surfaces

DubStack exposes AI-readable docs through public routes when indexing is enabled:

| Route | Purpose |
| --- | --- |
| `/llms.txt` | Compact AI-readable index. |
| `/llms-full.txt` | Larger AI-readable index with more page content. |
| `/mcp` | Public read-only MCP server for agents. |
| `/skill.md` | Agent skill instructions generated from the published docs. |

These routes use public docs content and public site metadata. They do not expose dashboard secrets.

## Public feedback

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `addons.feedback.thumbs_rating` | boolean | `false` | Shows Yes/No reader feedback on pages. |
| `addons.feedback.agent_feedback` | boolean | `false` | Allows the public MCP server to submit structured content feedback. |
| `addons.feedback.contextual_feedback` | boolean | `false` | Enables feedback actions from contextual UI surfaces. |
| `addons.feedback.code_snippet_feedback` | boolean | `false` | Enables feedback for code snippet surfaces when supported. |
| `addons.feedback.collect_reader_emails` | boolean | `false` | Allows feedback forms to request reader email addresses. |
| `addons.feedback.reader_email_disclaimer` | string | Empty | Short notice shown when collecting reader emails. |

```json
{
  "addons": {
    "feedback": {
      "thumbs_rating": true,
      "agent_feedback": true,
      "collect_reader_emails": false
    }
  }
}
```

Feedback settings can be managed from the dashboard add-ons page. Keep source-backed values reviewed when your site uses Git as the approval boundary.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Page is not searchable | Confirm it is in navigation and does not set `hidden`, `noindex`, or `searchable: false`. |
| AI tools cannot read docs | Confirm `addons.visibility.noindex` is `false`. |
| Metadata looks generic | Add page `title` and `description` frontmatter. |
| Feedback is missing | Enable `addons.feedback.thumbs_rating` and publish the config. |
