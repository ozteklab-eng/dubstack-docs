Use preview to check how content and configuration changes render before you rely on the live site.

Preview is especially important for MDX components, navigation edits, theme changes, and generated API reference pages.

## Open preview

From the editor toolbar, use the preview action to open the rendered page.

Depending on your editor setting, preview can open in the current workspace or in a new browser tab.

## What to check

Before publishing, verify:

- headings and table of contents render correctly
- callouts, cards, tabs, accordions, and code blocks look correct
- images and assets load
- navigation includes the right pages
- API reference pages show the correct method, path, parameters, body, and responses
- theme changes look correct in light and dark mode

## Preview versus live site

| Surface | Purpose |
| --- | --- |
| Editor preview | Fast local review while authoring. |
| Preview deployment | Share a branch-specific rendered site for review. |
| Live site | Production docs served from the deployment branch. |

Do not treat editor preview as the final production check. After publishing, open the live URL and verify the deployed page.

## Open preview in a new tab

Editor settings include an option to open live preview in a new browser tab.

Use this when you want to compare the editor and rendered docs side by side, or when you need to test the page at a different viewport size.
