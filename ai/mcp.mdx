DubStack exposes your documentation to AI tools through Model Context Protocol servers.

## Public docs MCP

Every published public docs site has a public MCP server at `/mcp`.

```text
https://your-docs-domain.com/mcp
```

Use this endpoint when you want AI tools to read and search your public docs. It does not require authentication and does not grant dashboard access.

## Public MCP compared to authoring surfaces

DubStack has separate MCP surfaces for separate jobs.

| Surface | Status | Audience | Access |
| --- | --- | --- | --- |
| Public docs MCP | Available | Readers, support teams, customers, and public AI tools | Read and search published public docs; submit documentation feedback when enabled. |
| Protected docs MCP | Reserved | Readers who need signed-in access to protected docs | Not currently available for public sites. |
| Authoring MCP | Reserved | Trusted team members and authoring agents | Not currently available from public docs sites. Authoring actions stay inside the dashboard, Git provider, Slack agent, and automation workflows. |

Use the public `/mcp` endpoint for reader-facing documentation search. Do not use it for private docs, branch edits, dashboard settings, or pull-request workflows.

The public server exposes tools for reading public docs and reporting documentation issues:

| Tool | What it does |
| --- | --- |
| `search` | Searches public indexed docs pages and returns titles, URLs, snippets, and file paths. |
| `query_docs_filesystem` | Reads and searches a virtual filesystem of your published docs pages with commands like `tree`, `cat`, and `rg`. |
| `submit_feedback` | Reports a documentation issue when an agent finds a page that is incorrect, outdated, confusing, or incomplete. This tool is available only when the **Agent feedback** add-on is enabled. |

## How agents use it

AI tools decide when to call MCP tools while generating a response.

A common flow is:

1. Call `search` to find likely pages.
2. Call `query_docs_filesystem` to read exact page content from the virtual docs filesystem.
3. Answer the user with links to the source pages.
4. If `submit_feedback` is available, call it only when the agent finds a substantive documentation issue.

MCP reads from the published docs site. It does not read unpublished editor changes, private dashboard state, or source repository secrets.

## Tool inputs

### `search`

```json
{
  "query": "custom domains",
  "limit": 5
}
```

Optional `language` and `version` fields are reserved for multilingual and versioned sites.

### `query_docs_filesystem`

```json
{
  "command": "tree / -L 2"
}
```

Supported commands include `ls`, `tree`, `find`, `cat`, `head`, `tail`, `rg`, and `grep`.

Examples:

```bash
cat /quickstart.mdx
head -80 /api-reference/introduction.mdx
rg -n "custom domain" /
```

### `submit_feedback`

This tool is advertised only when **Settings > Deployment > Add-ons > Agent feedback** is enabled for the deployment.

```json
{
  "path": "/quickstart",
  "feedback": "The page says to open a settings page that no longer exists."
}
```

Feedback is stored with the deployment feedback analytics for the site. Use it for documentation-quality issues, not for normal reader questions.

## Discovery

DubStack publishes MCP discovery documents automatically:

| Path | Purpose |
| --- | --- |
| `/mcp` | Public MCP server and GET discovery response. |
| `/.well-known/mcp` | Discovery document. |
| `/.well-known/mcp.json` | JSON discovery document alias. |
| `/.well-known/mcp/server-card.json` | Single server card. |
| `/.well-known/mcp/server-cards.json` | Server-card list. |

`/.well-known/mcp` and `/.well-known/mcp.json` return the same discovery document.

Server-card responses include tool metadata and safety annotations so MCP clients can inspect available tools before connecting.

The public server reserves `/mcp` for MCP. Do not create docs pages or redirects at that path.

## Tool safety annotations

The server card describes tool behavior so MCP clients can show the right approval prompts:

| Tool | Read-only | Idempotent | Notes |
| --- | --- | --- | --- |
| `search` | Yes | Yes | Searches indexed public docs content only. |
| `query_docs_filesystem` | Yes | Yes | Reads a virtual filesystem generated from published docs. |
| `submit_feedback` | No | No | Creates a feedback record for a documentation-quality issue when Agent feedback is enabled. |

All public MCP tools operate against the current published docs site, not the open web.

## Skill file

Your docs site also serves a generated skill file:

```text
https://your-docs-domain.com/skill.md
```

Agents connected to your MCP server can discover the same skill through MCP resources. The skill tells agents to use your current published docs as the source of truth and points them at your public MCP server.

For the rest of the AI-readable docs files, see [AI discovery files](/ai/ai-discovery-files).

## MCP resources

The public MCP server exposes generated skill files as MCP resources when the client supports resource discovery.

Use resources for durable agent instructions, then use tools for live retrieval:

1. Read the generated skill resource to understand how the docs site wants agents to behave.
2. Use `search` to find candidate pages.
3. Use `query_docs_filesystem` to read exact published page content.
4. If `submit_feedback` is available, use it only for substantive documentation issues.

## Connect from an MCP client

Claude Code example:

```bash
claude mcp add --transport http my-docs https://your-docs-domain.com/mcp
```

Generic MCP JSON config:

```json
{
  "mcpServers": {
    "my-docs": {
      "type": "http",
      "url": "https://your-docs-domain.com/mcp"
    }
  }
}
```

Codex TOML config:

```toml
[mcp_servers.my-docs]
url = "https://your-docs-domain.com/mcp"
```

For clients with a UI connector form, use:

| Field | Value |
| --- | --- |
| Name | A short name for the docs site |
| URL | `https://your-docs-domain.com/mcp` |
| Transport | HTTP |
| Authentication | None for public docs |

## Protected and authoring access

Do not use the public `/mcp` endpoint for private docs or dashboard write access.

Protected docs access and dashboard content-management MCP are separate product surfaces. Until those surfaces are available, use the dashboard, connected Git provider, Slack agent, and automation workflows for authenticated authoring tasks.

## Troubleshooting

If an MCP client cannot connect:

1. Confirm the public docs site loads.
2. Open `/mcp` in a browser and verify it returns discovery JSON.
3. Open `/.well-known/mcp/server-card.json` and confirm the expected tools are listed.
4. Check that AI discovery/indexing is not disabled for the deployment.
5. Republish the site if the latest docs content or add-on settings have not synced yet.
