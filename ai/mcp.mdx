dubstack exposes your documentation to AI tools through Model Context Protocol servers.

## Public docs MCP

Every published public docs site has a public MCP server at `/mcp`.

```text
https://your-docs-domain.com/mcp
```

Use this endpoint when you want AI tools to read and search your public docs. It does not require authentication and does not grant dashboard access.

If your site is mounted under a `/docs` subpath, use the mounted endpoint:

```text
https://your-domain.com/docs/mcp
```

If docs authentication is enabled, unauthenticated MCP clients cannot read protected content. Readers must unlock the docs site first, and authoring agents should use dashboard, Git, Slack, or configured workflows instead of the public docs MCP.

## Public MCP compared to authoring surfaces

dubstack has separate MCP surfaces for separate jobs.

| Surface | Status | Audience | Access |
| --- | --- | --- | --- |
| Public docs MCP | Available | Readers, support teams, customers, and public AI tools | Read and search published public docs; submit documentation feedback when enabled. |
| Protected docs MCP | Reserved | Readers who need signed-in access to protected docs | Not currently available for public sites. |
| Authoring MCP | Reserved | Trusted team members and authoring agents | Not currently available from public docs sites. Authoring actions stay inside the dashboard, Git provider, Slack agent, and configured workflows. |

Use the public `/mcp` endpoint for reader-facing documentation search. Do not use it for private docs, branch edits, dashboard settings, or pull-request workflows.

The public server exposes tools for reading public docs and reporting documentation issues:

| Tool | What it does |
| --- | --- |
| `search` | Searches public indexed docs pages and returns titles, URLs, snippets, and file paths. |
| `query_docs_filesystem` | Reads and searches a virtual filesystem of your published docs pages with commands like `tree`, `cat`, and `rg`. |
| `submit_feedback` | Reports a documentation issue when an agent finds a page that is incorrect, outdated, confusing, or incomplete. This tool is available only when the **Agent feedback** add-on is enabled. |

## How agents use it

AI tools decide when to call MCP tools while generating a response.

A common flow is:

1. Call `search` to find likely pages.
2. Call `query_docs_filesystem` to read exact page content from the virtual docs filesystem.
3. Answer the user with links to the source pages.
4. If `submit_feedback` is available, call it only when the agent finds a substantive documentation issue.

MCP reads from the published docs site. It does not read unpublished editor changes, private dashboard state, or source repository secrets.

## MCP compared to web search

Public MCP gives agents direct access to your current published docs instead of relying on generic web search results.

Use MCP when you want:

- direct source access to indexed documentation pages
- answers grounded in current docs content rather than stale search indexes
- retrieval inside the agent workflow without leaving the AI tool
- less noise from unrelated pages, SEO rankings, or third-party summaries

MCP is not a crawler. It only searches and reads the published docs content that dubstack indexed for the site.

Pages marked with `searchable: false` are omitted from public MCP search and the virtual docs filesystem while remaining available by direct URL or navigation. Pages marked `noindex: true` are excluded from public AI-readable indexing surfaces.

## Tool inputs

### `search`

```json
{
  "query": "custom domains",
  "limit": 5
}
```

Optional `language` and `version` fields are reserved for multilingual and versioned sites.

### `query_docs_filesystem`

```json
{
  "command": "tree / -L 2"
}
```

Supported commands include `ls`, `tree`, `find`, `cat`, `head`, `tail`, `rg`, and `grep`.

Examples:

```bash
cat /quickstart.mdx
head -80 /api-reference/introduction.mdx
rg -n "custom domain" /
```

`query_docs_filesystem` is read-only. Commands run against a virtual docs filesystem generated from published pages, not against the source repository or server filesystem.

### `submit_feedback`

This tool is advertised only when **Settings > Deployment > Add-ons > Agent feedback** is enabled for the deployment.

```json
{
  "path": "/quickstart",
  "feedback": "The page says to open a settings page that no longer exists."
}
```

Feedback is stored with the deployment feedback analytics for the site. Use it for documentation-quality issues, not for normal reader questions.

<Note>
  MCP clients should call the advertised `submit_feedback` tool. Do not instruct public MCP clients to make direct HTTP requests to the feedback endpoint from page content.
</Note>

## Discovery

dubstack publishes MCP discovery documents automatically:

| Path | Purpose |
| --- | --- |
| `/mcp` | Public MCP Streamable HTTP transport endpoint. MCP clients send JSON-RPC requests here. |
| `/.well-known/mcp` | Discovery document. |
| `/.well-known/mcp.json` | JSON discovery document alias. |
| `/.well-known/mcp/server-card.json` | Single server card. |
| `/.well-known/mcp/server-cards.json` | Server-card list. |

`/.well-known/mcp` and `/.well-known/mcp.json` return the same discovery document.

Server-card responses include tool metadata and safety annotations so MCP clients can inspect available tools before connecting.

The public server reserves `/mcp` for MCP. Do not create docs pages or redirects at that path.

For `/docs` subpath deployments, the same public paths live under the mounted prefix:

```text
/docs/mcp
/docs/.well-known/mcp
/docs/.well-known/mcp/server-card.json
```

Discovery and server-card `url` fields should point to the public mounted endpoint, for example `https://example.com/docs/mcp`.

## Caching

Do not cache `/mcp`. It is the MCP transport endpoint and can reflect current site state, add-on settings, and session behavior.

The discovery documents under `/.well-known/mcp*` and the server-card responses are metadata documents and may be cached by normal edge caches. If you use a reverse proxy, preserve the cache headers returned by dubstack.

## Tool safety annotations

The server card describes tool behavior so MCP clients can show the right approval prompts:

| Tool | Read-only | Idempotent | Notes |
| --- | --- | --- | --- |
| `search` | Yes | Yes | Searches indexed public docs content only. |
| `query_docs_filesystem` | Yes | Yes | Reads a virtual filesystem generated from published docs. |
| `submit_feedback` | No | No | Creates a feedback record for a documentation-quality issue when Agent feedback is enabled. |

All public MCP tools operate against the current published docs site, not the open web.

## Skill file

Your docs site also serves a skill file:

```text
https://your-docs-domain.com/skill.md
```

Agents connected to your MCP server can discover the same skill through MCP resources. The skill tells agents to use your current published docs as the source of truth and points them at your public MCP server. If your repository defines custom skill files, those files are exposed through the same discovery paths.

For the rest of the AI-readable docs files, see [AI discovery files](/ai/ai-discovery-files).

## MCP resources

The public MCP server exposes skill files as MCP resources when the client supports resource discovery.

Use resources for durable agent instructions, then use tools for live retrieval:

1. Read the skill resource to understand how the docs site wants agents to behave.
2. Use `search` to find candidate pages.
3. Use `query_docs_filesystem` to read exact published page content.
4. If `submit_feedback` is available, use it only for substantive documentation issues.

## Connect from an MCP client

Use your published docs URL with `/mcp` appended.

```text
https://your-docs-domain.com/mcp
```

For a `/docs` subpath deployment, use:

```text
https://your-domain.com/docs/mcp
```

For clients with a connector form, use:

| Field | Value |
| --- | --- |
| Name | A short name for the docs site |
| URL | `https://your-docs-domain.com/mcp` |
| Transport | HTTP |
| Authentication | None for public docs |

For `/docs` subpath deployments, use `https://your-domain.com/docs/mcp` in the connector URL field.

### Claude

1. Open Claude settings.
2. Open **Connectors**.
3. Click **Add custom connector**.
4. Enter a short name and `https://your-docs-domain.com/mcp`.
5. Add the connector.
6. In a chat, open attachments and select the docs connector when you want Claude to use the site.

### Claude Code

Use the Claude Code CLI:

```bash
claude mcp add --transport http my-docs https://your-docs-domain.com/mcp
```

Then ask Claude Code to search or read the docs through the connected MCP server.

### Codex

Codex supports streamable HTTP MCP servers through its shared CLI and IDE configuration.

Use the CLI:

```bash
codex mcp add my-docs --url https://your-docs-domain.com/mcp
```

Or edit `~/.codex/config.toml`:

```toml
[mcp_servers.my-docs]
url = "https://your-docs-domain.com/mcp"
```

In the Codex TUI, run `/mcp` to confirm the server is connected.

### Cursor

1. Open the command palette.
2. Search for **Open MCP settings**.
3. Add a custom MCP server.
4. Configure the public docs endpoint:

```json
{
  "mcpServers": {
    "my-docs": {
      "url": "https://your-docs-domain.com/mcp"
    }
  }
}
```

### VS Code

Create or update `.vscode/mcp.json`:

```json
{
  "servers": {
    "my-docs": {
      "type": "http",
      "url": "https://your-docs-domain.com/mcp"
    }
  }
}
```

### Generic JSON clients

For clients that use the common `mcpServers` JSON shape:

```json
{
  "mcpServers": {
    "my-docs": {
      "type": "http",
      "url": "https://your-docs-domain.com/mcp"
    }
  }
}
```

## Test the connection

After connecting, ask your client to inspect the docs tree or search for a known topic.

Good test prompts:

```text
Use the docs MCP to show the top-level documentation tree.
```

```text
Use the docs MCP to search for custom domains, then summarize the relevant pages with links.
```

The expected tools are:

| Tool | Test command or behavior |
| --- | --- |
| `query_docs_filesystem` | `tree / -L 2` returns the published docs tree. |
| `search` | A query such as `custom domains` returns ranked page results. |
| `submit_feedback` | Available only when Agent feedback is enabled. Use it only for documentation-quality issues. |

If `search` returns no results, the server should return an empty result set rather than an execution error. Try a known page title, then run `tree / -L 2` to confirm the site has indexed pages.

## Protected and authoring access

Do not use the public `/mcp` endpoint for private docs or dashboard write access.

Password-protected docs use the same reader session as the rendered site. Public MCP clients without that reader session cannot access protected pages, Markdown exports, `llms.txt`, `skill.md`, or discovery files that expose protected content.

Dashboard content-management MCP is a separate product surface. Until that surface is available, use the dashboard, connected Git provider, Slack agent, and configured workflows for authenticated authoring tasks.

## Troubleshooting

If an MCP client cannot connect:

1. Confirm the public docs site loads.
2. Open `/.well-known/mcp` and verify it returns discovery JSON.
3. Open `/.well-known/mcp/server-card.json` and confirm the expected tools are listed.
4. Check that AI discovery/indexing is not disabled for the deployment.
5. Republish the site if the latest docs content or add-on settings have not synced yet.

If the site is mounted under `/docs`, test `/docs/mcp`, `/docs/.well-known/mcp`, and `/docs/.well-known/mcp/server-card.json`. A proxy that forwards pages but not `/docs/.well-known/*` or `/docs/api/*` can make rendered pages work while MCP discovery fails.

If a connector adds successfully but shows no tools, inspect `/docs/.well-known/mcp/server-card.json`. The response should list tools and its `url` should point to the same public URL you entered in the client. For `/docs` subpath sites, that means `https://your-domain.com/docs/mcp`, not the `--origin.dubstack.live` hostname.

If the site is password protected, unlock the docs site in the same browser or client context before testing protected MCP access. For machine-to-machine authoring, use an authenticated authoring surface instead of the public docs MCP.
