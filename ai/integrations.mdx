Integrations let agents and workflows pull live context from the tools where product work already happens.

Use integrations when a documentation update depends on a conversation, issue, release plan, or support signal that is not already in the published docs.

## What integrations are for

Integrations can help the agent:

- answer dashboard questions with additional workspace context
- draft documentation updates from connected tool context
- enrich workflows with selected collaboration or issue-tracking context
- notify teams when workflow runs finish

They do not change the source of truth. Documentation changes still write through the connected Git provider.

Connected providers are used as tools for a specific agent or workflow run. dubstack does not proactively read connected apps in the background, and the run should only fetch provider context when that context is relevant to the task.

Only connected integrations are available to the agent and workflow runner. Catalog integrations appear in the dashboard so teams can see the planned context model, but a provider marked **Coming soon**, **Upgrade**, or **Unavailable** is not passed to runs.

Availability can depend on plan, repository access, workspace authorization, and provider configuration.

For scope, eligibility, missing scopes, and disconnect behavior, see [Integration permissions and scopes](/ai/integration-permissions). For the stable behavior model behind each provider, see [Connector capabilities](/ai/connector-capabilities).

## Connect an integration

Admins and editors can connect shared integrations on behalf of the organization. Viewers can use enabled read-only surfaces when their role allows it, but they cannot configure provider access.

1. Open the dashboard.
2. Select the deployment.
3. Go to **Settings > Organization > Integrations**.
4. Choose the integration.
5. Complete the provider authorization flow.
6. Return to the dashboard and confirm the integration status is connected.

Some integrations also appear inside the **Agent** setup flow when they are required for that surface.

Some providers need an additional configuration step before authorization completes. For example, issue-tracking or knowledge-base providers can ask for a workspace URL, site subdomain, project, or API key before the provider connection is saved.

## Shared and personal connections

Integrations connect in one of two ways:

- **Shared integrations** are authorized once for the organization and can be used by eligible agent or workflow surfaces.
- **Personal integrations** are authorized by individual teammates and stay scoped to the user who connected them.

Use shared integrations for team-owned systems such as Slack, Jira, Linear, Notion, Confluence, and CRM or support platforms. Use personal integrations for user-specific systems such as calendar or drive context.

## Use integrations in workflows

Some workflows can include connected integrations as context sources or notification sinks.

To enable integrations for a workflow:

1. Open **Automate > Workflows**.
2. Choose the workflow.
3. Open the workflow settings drawer.
4. Select the connected integrations in the available integrations section.
5. Save the workflow.

Only providers already connected for the organization or user appear as selectable workflow context. The workflow run fetches live context only when it needs that provider for the configured task; it does not scan connected apps outside the selected workflow scope.

## Scope and safety

Integrations are scoped to the current organization and deployment.

The agent should only use integration context when:

- the integration is connected
- the current user is allowed to configure or use it
- the request needs that external context
- the workflow or agent run explicitly selects it

<Callout type="warning">
  Do not paste private credentials into prompts or docs. Use provider authorization and dashboard-managed integration settings instead.
</Callout>

## Reconnect or disconnect

Reconnect an integration when the provider token expires, an admin revokes the app, or the required scopes change.

1. Go to **Settings > Organization > Integrations**.
2. Choose the provider.
3. Disconnect or reconnect the provider.
4. Complete the provider authorization flow again.

Disconnecting a shared integration removes it for everyone in the organization. Disconnecting a personal integration removes only that user's connection.

Disconnecting cuts off future live reads from that provider. Existing docs, pull requests, merge requests, and historical run records remain in place because they are separate review or audit artifacts.
