AI usage reporting helps teams understand how assistant, agent, Slack, and workflow activity contributes to their workspace allowance.

The dashboard is the source of truth for your current plan, allowance, billable status, and upgrade options.

## What counts as AI usage

AI usage can be recorded from these surfaces:

| Surface | Example activity |
| --- | --- |
| Public assistant | A reader asks a question from the published docs assistant. |
| Dashboard agent | A teammate asks the dashboard agent to answer, draft, or inspect docs. |
| Slack agent | A teammate mentions the agent in Slack and receives a docs answer or draft. |
| Workflows | A configured workflow drafts docs updates, changelog entries, link fixes, or audits. |

Public MCP search and filesystem reads are tracked separately from generation-heavy assistant or agent runs.

Repository sync and one-time repository copy actions are not AI usage when they only move docs files between Git providers or published artifacts. They may be rate limited and audited, but they do not consume AI credits by themselves. Scheduled repository-copy workflows are workflow runs, so they consume automation credits and appear in the usage ledger.

## Usage ledger

Each AI run can record:

| Field | Meaning |
| --- | --- |
| `interaction_source` | Where the request came from, such as public assistant, dashboard, Slack, or workflow. |
| `run_type` | The kind of action being performed. |
| `billing_unit` | The reporting unit used for credit estimation. |
| `status` | Run outcome, such as started, succeeded, failed, skipped, cancelled, or no answer. |
| `profile_id` | The assistant or agent profile used for routing. |
| `provider` and `model` | Model route information shown to authorized admins where available. |
| `input_tokens`, `output_tokens`, `total_tokens` | Token usage reported by the model provider when available. |
| `credits_estimated` | Estimated credit usage for reporting. |
| `credits_charged` | Charged credits when billing is active for the run. |

Usage metadata is sanitized before storage. Prompt text, answers, secrets, API keys, cookies, authorization values, and email addresses are not stored as usage metadata fields.

## Credit estimates

Credit estimates are reporting units. They help compare different AI surfaces before final billing or overage behavior is applied.

Current estimate units include:

| Usage unit | Typical source | Average estimate |
| --- | --- | --- |
| `assistant_response` | Public assistant responses. | 23 credits |
| `editor_agent_run` | Dashboard agent runs. | 115 credits |
| `slack_agent_run` | Slack agent interactions. | 110 credits |
| `workflow_update_from_code_changes` | Code-change documentation workflows. | 180 credits |
| `workflow_update_from_assistant_conversations` | Assistant-conversation improvement workflows. | 212 credits |
| `workflow_user_feedback_improvements` | Page feedback improvement workflows. | 245 credits |
| `workflow_support_feedback_improvements` | Support-feedback improvement workflows when enabled. | 285 credits |
| `workflow_broken_link_detection` | Broken-link detection and repair workflows. | 285 credits |
| `workflow_changelog` | Changelog draft workflows. | 223 credits |
| `workflow_seo_audit` | SEO audit workflows. | 422 credits |
| `workflow_translations` | Translation workflows when enabled for the deployment. | 913 credits |
| `workflow_typo_check` | Grammar and typo workflows. | 330 credits |
| `workflow_writing_style` | Style-guide workflows. | 235 credits |

Catalog-only workflows do not charge credits until a runner is available and a run is actually queued.

Exact allowance, charging, and overage behavior can depend on your plan and workspace configuration.

## Plan availability

AI features are plan-gated.

| Plan state | Expected behavior |
| --- | --- |
| Free | AI assistant and agent usage may be unavailable unless a trial or entitlement enables it. |
| Pro | AI assistant, agent, and workflow usage can draw from the workspace allowance. |
| Enterprise | AI usage can use custom allowances, model routing, and enterprise controls configured for the workspace. |

If a feature is locked, check the dashboard reason before assuming the site is misconfigured.

## Allowance model

AI credits are a workspace-level allowance shared across assistant, agent, Slack, and workflow surfaces.

This means the same monthly allowance can be consumed by:

- public assistant answers
- dashboard agent requests
- Slack agent questions and draft pull requests
- scheduled or event-driven workflows

Free workspaces can use eligible trial or preview entitlements when available, but ongoing AI usage is intended for Pro and Enterprise workspaces. Enterprise workspaces can receive custom allowances, routing, and operational controls.

<Callout type="info">
  Credits are reporting and billing units, not raw model tokens. Token usage, retrieval cost, model route, and workflow complexity can all contribute to the credit estimate.
</Callout>

## Workflow cost expectations

Workflow runs vary more than assistant answers because they may inspect multiple files, retrieve repository context, draft changes, and prepare a pull request.

Typical run cost depends on:

- the workflow type
- the number of files or pages inspected
- the amount of context pulled from connected tools
- whether the run drafts content, only audits, or exits with no suggested change
- the assistant profile and model route selected for the workspace

For predictable usage, schedule workflows deliberately and keep their scope narrow. For example, run broad maintenance workflows weekly, but run targeted link or typo checks after relevant content changes.

## Review usage

Use dashboard analytics and product pages to review usage:

- **Settings > Workspace > Usage** shows AI runs, credits used, model cost estimates, retrieval requests, breakdowns, and recent activity for the selected site.
- **Analytics > Assistant** shows assistant usage and related reader behavior when available.
- **Products > Assistant** shows assistant readiness, retrieval diagnostics, and recent usage paths.
- **Products > Workflows** shows workflow runs, status, and usage-related metadata.
- **Settings > Workspace > Billing** shows the current plan and allowance state.

## Reduce unnecessary usage

- Ask focused questions instead of broad multi-page requests.
- Scope workflows to specific repositories, labels, branches, or schedules.
- Prefer review-mode workflows for production docs.
- Disable workflows that are no longer needed.
- Use feedback and analytics to prioritize high-impact docs changes.
