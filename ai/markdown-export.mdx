Markdown export gives readers a clean text version of the current page so they can reuse docs content in AI tools, support workflows, and internal notes without copying the rendered site chrome.

DubStack exposes Markdown through page contextual actions, page-level `.md` URLs, and content negotiation with `Accept: text/markdown` or `Accept: text/plain`. Site-level AI indexes are available through [`llms.txt`](/ai/llms-indexes) and [`llms-full.txt`](/ai/llms-indexes).

## Copy a page as Markdown

When contextual actions are enabled, the **Copy page** action copies the current page content as Markdown.

Use this when you want to paste a page into:

- an AI assistant conversation
- an issue or pull request
- a support reply
- an internal handoff note

The copied content comes from the published page content. It does not include dashboard state, unpublished editor changes, private repository files, or team-only notes.

## View as Markdown

The **View as Markdown** action opens the current page content as a Markdown document in the browser.

This is useful when you want to inspect the raw text shape that an AI tool receives before copying or sharing it.

## Open a page as Markdown

Append `.md` to any published documentation page URL to fetch the clean Markdown version of that page.

```txt
https://docs.example.com/getting-started.md
https://docs.example.com/api-reference/endpoint/create-user.md
```

The response uses `text/markdown; charset=utf-8` and includes a documentation-index note that points agents to `/llms.txt` before they explore individual pages.

You can also request exported content from the normal page URL with an `Accept` header.

```bash
curl -H "Accept: text/markdown" https://docs.example.com/getting-started
curl -H "Accept: text/plain" https://docs.example.com/getting-started
```

`Accept: text/markdown` returns `text/markdown; charset=utf-8`. `Accept: text/plain` returns the same exported page content with `text/plain; charset=utf-8` for clients that only request plain text.

Root pages are available at `/.md`.

```txt
https://docs.example.com/.md
```

API reference endpoint pages include an `OpenAPI` section for the current operation so AI tools can read the method, path, parameters, request body, responses, and schemas without loading the visual API playground.

## Configure Markdown actions

Contextual actions are configured in `dubstack.json`.

```json
{
  "contextual": {
    "enabled": true,
    "options": ["copy", "view", "claude", "chatgpt", "perplexity"],
    "default": "copy"
  }
}
```

Use `copy` for clipboard export and `view` for a readable Markdown view.

## Use with external AI tools

External AI actions send the tool a prompt for the current page context.

Before enabling external AI actions, confirm the page content is safe to send to that destination. Public docs are already visible to readers, but external AI tools can have separate retention, workspace, and privacy policies.

<Callout type="warning">
  Do not publish secrets, private customer data, unreleased plans, or internal procedures in public documentation.
</Callout>

## Site-wide Markdown files

For whole-site ingestion, use the generated AI index files instead of copying pages one by one.

| File | Use it for |
| --- | --- |
| `/llms.txt` | A compact index of public pages. |
| `/llms-full.txt` | A full text bundle of published pages. |
| `/skill.md` | Agent instructions and MCP discovery guidance. |

See [AI index files](/ai/llms-indexes) and [Generated skill file](/ai/generated-skill-file) for the generated file behavior.

## Authentication behavior

Markdown export follows the same reader access rules as the rendered page.

| Site access | Markdown behavior |
| --- | --- |
| Public docs | `.md` URLs and Markdown `Accept` requests are public. |
| Password-protected docs | Readers must unlock the site before Markdown content is returned. |
| `/docs` subpath | Markdown URLs stay under the mounted path, such as `https://example.com/docs/quickstart.md`. |

For protected docs, unauthenticated Markdown requests return an authentication response instead of page content. This prevents AI tools, MCP clients, and crawlers from bypassing the rendered site login.

For setup details, see [Docs authentication](/deployment/docs-authentication).

## Troubleshooting

If Markdown actions are missing:

1. Confirm `contextual.enabled` is `true`.
2. Confirm `copy` or `view` is listed in `contextual.options`.
3. Publish the branch that contains the `dubstack.json` update.
4. Refresh the published page after the update completes.

If copied Markdown is stale, run a manual update from the dashboard and wait for the deployment activity to complete.

If a `.md` URL returns `404`, check whether:

1. The page exists in the published deployment.
2. Public indexing is enabled for the deployment.
3. The page does not set `noindex: true` in frontmatter.
