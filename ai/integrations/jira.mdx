The Jira integration gives the dashboard agent controlled access to issue context.

Use it when a documentation update depends on product work tracked in Jira, such as feature issues, bug reports, release epics, or support-driven documentation gaps.

## What Jira can do

Jira can provide:

- issue keys, summaries, status, issue type, project, updated timestamp, links, and recent comments for dashboard agent answers
- issue context for Slack agent requests when Jira context is requested
- issue context for workflows that support integrations
- bounded JQL-based context for recurring documentation workflows

Jira is a read-only context source. It does not write documentation, update issues, read arbitrary Jira fields, or inspect issue attachments. The agent writes docs changes through the connected Git provider.

## Connection scope

Jira is a shared integration. An admin or editor connects one Atlassian workspace for the organization, and eligible agent or workflow surfaces can use that connection when Jira context is explicitly requested or selected.

The agent inherits the access of the Atlassian account that authorized the connection. It can read only issues and comments that account can already view in Jira.

To narrow access, restrict the connected Atlassian account in Jira or connect an account that belongs only to the projects you want documentation workflows to inspect.

## Requirements

Before connecting Jira, confirm:

- your organization has Enterprise access or an active trial that includes integration features
- you know the Atlassian site subdomain to connect
- the Jira OAuth app is configured for the environment
- your Atlassian account can access the issues you want the agent to use
- the deployment has repository authoring access if you want pull requests

## Connect Jira

1. Open the dashboard.
2. Select the deployment.
3. Go to **Settings > Organization > Integrations**.
4. Choose **Jira**.
5. Enter the Atlassian site subdomain.
6. Authorize Jira access.
7. Return to the dashboard and confirm Jira is connected.

The dashboard stores the selected workspace and granted scopes for that organization or deployment scope.

## Use Jira context with the agent

Ask for Jira context when the issue tracker contains the source details.

The agent collects Jira context only when your request includes a Jira issue key or an inline `jql:` query.

If you mention Jira without a specific issue key or query, the agent asks for a more specific issue or filter instead of sweeping your workspace.

Examples:

```text
Use Jira context for PROJ-123 and draft a migration note for the docs.
```

```text
Use Jira context with jql: project = BILLING AND labels = docs ORDER BY updated DESC, then summarize the open documentation issues.
```

```text
Use Jira context with jql: project = DOCS AND statusCategory != Done ORDER BY updated DESC, then draft a docs backlog summary.
```

Keep the query narrow. The agent does not infer projects, search arbitrary Jira fields, or inspect unrelated issues.

<Callout type="info">
  Jira context queries must include a search restriction, such as a project, issue key, label, fix version, or updated-date window. Broad queries like `ORDER BY updated DESC` are rejected safely instead of scanning the whole workspace.
</Callout>

## Use Jira context in workflows

Workflows that support integrations can enable Jira context.

When configuring the workflow, set:

| Setting | Purpose |
| --- | --- |
| JQL | Narrows which issues the workflow can read. |
| Limit | Caps the number of issues included in a run. The default is 5 and the maximum is 10. |

Keep JQL narrow. Smaller context usually produces better documentation updates and reduces unnecessary token usage.

Unbounded JQL is blocked. Use a project, label, issue key, fix version, status, or date window so the workflow reads only the issues relevant to the documentation update.

For each issue, the workflow can include the issue summary, status, issue type, project, updated timestamp, issue link, and up to two recent comments. It does not include issue attachments or arbitrary custom fields.

Example JQL:

```text
project = DOCS AND statusCategory != Done ORDER BY updated DESC
```

## Disconnect Jira

1. Open **Settings > Organization > Integrations**.
2. Find Jira.
3. Choose **Disconnect**.

Disconnecting Jira stops new Jira context collection. Existing docs, pull requests, and previous run records are not removed.
