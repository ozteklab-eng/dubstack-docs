GitHub is the primary connected-source provider for dubstack docs.

Use the GitHub App when your documentation source lives in a GitHub repository and you want automatic updates, preview deployments, editor commits, agent draft pull requests, and workflow-driven documentation changes.

## When you need the GitHub App

| Repository type | GitHub App required? |
| --- | --- |
| Hosted starter repository created by dubstack | No, the hosted source is managed for you. |
| Your own GitHub repository | Yes, install the app and grant access to the docs repository. |
| Private GitHub repository | Yes, install the app with access to the private repository. |

The dashboard shows the active repository, branch, last sync time, and app installation state in **Settings > Deployment > Git settings**.

## Connect GitHub

<Steps>
  <Step title="Open Git settings">
    In the dashboard, go to **Settings > Deployment > Git settings**.
  </Step>

  <Step title="Choose GitHub">
    Select **GitHub** from the provider cards.
  </Step>

  <Step title="Install or manage the GitHub App">
    Click **Install GitHub App** or **Grant Repository Access**.

    GitHub opens the app installation flow. Choose the account or organization that owns the docs repository.
  </Step>

  <Step title="Select repository access">
    Grant access to the docs repository.

    You can choose all repositories, but the safer default is **Only select repositories** and then selecting the docs repository plus any repositories you intentionally want the agent or workflows to read as context.
  </Step>

  <Step title="Select the source">
    Back in Git settings, select the repository, deployment branch, and docs root.

    Enable **Docs are in a subdirectory** only when `dubstack.json` is below the repository root.
  </Step>

  <Step title="Save and verify">
    Save the connection, then run a manual update.

    The manual update verifies that DubStack can read the selected repository and publish artifacts for the live site.
  </Step>
</Steps>

## Recommended repository structure

At minimum, the repository should include:

```text
dubstack.json
index.mdx
quickstart.mdx
```

For richer sites, include:

- `api-reference/openapi.json` or another configured OpenAPI spec path
- image and asset files used by pages
- reusable snippets
- folders that match the slugs in `dubstack.json`

## GitHub App access

Grant access only to the repositories dubstack needs.

The GitHub App is used for:

- reading docs source files
- receiving repository events
- creating branches and draft pull requests when agent authoring is enabled
- creating preview deployments for supported branch or pull request workflows
- updating docs files from the dashboard editor where allowed

If your organization uses branch protection, keep it enabled. Agent and editor changes should still follow the repository's review rules.

## Permissions

GitHub shows the permissions requested by the app during installation or when permissions change.

| Permission | Why DubStack uses it |
| --- | --- |
| `metadata: read` | Identify repositories and installation ownership. |
| `contents: read` | Read source files during sync, preview, search, assistant, and MCP indexing. |
| `contents: write` | Commit editor, agent, and workflow changes when authoring is enabled. |
| `pull_requests: write` | Create draft pull requests for agent and workflow updates. |
| `checks` or deployment-related permissions | Attach provider-native status signals for supported preview and deployment flows. |

<Callout type="info">
  GitHub sources use the GitHub App installation. Do not paste personal access tokens for GitHub source sync.
</Callout>

If authoring is not ready, the readiness panel may report missing GitHub write permissions. Update the app installation in GitHub, then return to Git settings and run a manual update.

## Dashboard states

Use the Git settings card to confirm the active source.

| State | Meaning |
| --- | --- |
| Hosted repository | DubStack manages the starter source for you. A separate GitHub App install is not required until you move to your own repository. |
| Active GitHub repository | The site publishes from the listed repository and branch. |
| GitHub app not installed | The source points to GitHub, but DubStack does not have a usable installation for the repository. |
| Last synced | The most recent successful sync time for the active provider. |

Use **Settings > Deployment > GitHub app** to install the app, open GitHub installation settings, or grant access to additional repositories.

Use **Settings > Account** to confirm whether your user has GitHub authorization connected for account-level authoring flows.

## Revalidate after repository changes

Revalidate the connection after any external GitHub change that affects access or source layout.

Common triggers:

- repository rename or transfer
- branch rename
- GitHub App uninstall or reinstall
- installation repository-access change
- organization ownership or repository-admin permission change
- branch protection change
- moving `dubstack.json` into or out of a subdirectory

Recommended recovery path:

1. Open **Settings > Deployment > GitHub app**.
2. Confirm the correct GitHub account or organization is installed.
3. Open the GitHub installation settings and confirm the repository is selected.
4. Return to **Settings > Deployment > Git settings**.
5. Confirm the repository, branch, and subdirectory settings.
6. Run a manual update.
7. Check the activity feed or deployment history for the resulting sync status.

## Hosted starter to GitHub

If you skipped Git during onboarding, your site can start with a hosted repository. Move to your own GitHub repository when you want full repository ownership.

Recommended path:

1. Open **Settings > Deployment > Git settings**.
2. Choose GitHub as the target provider.
3. Install the GitHub App if needed.
4. Clone or copy the hosted docs source into your GitHub organization.
5. Select the new repository and branch.
6. Run a manual update.
7. Confirm the live site matches the previous hosted version.

## Troubleshooting

### Repository is missing from the picker

Check that the GitHub App is installed on the organization or account that owns the repository, and that the repository is included in the installation's repository access list.

### Updates do not run after push

Check:

- the push went to the configured branch
- the GitHub App is still installed
- the repository has not been renamed or transferred
- the activity feed shows the latest webhook or manual update

### Agent cannot open a pull request

Check that the GitHub App has access to the repository and that branch protection allows app-created branches and pull requests. The app should not need to bypass required reviews.

### Manual update works but webhook updates do not

Reinstall or reauthorize the GitHub App, then run another manual update to verify the connection.
