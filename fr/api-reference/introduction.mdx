dubstack peut générer une documentation API à partir de spécifications OpenAPI, de pages de points de terminaison MDX rédigées manuellement ou d'un mélange des deux.

Utilisez cette section pour deux tâches liées :

- apprendre à documenter vos propres API de produits dans un site de documentation dubstack
- explorer les points de terminaison publics exposés par chaque site dubstack publié pour le MCP, les index LLM, le chat de l'assistant et le playground API

## Chemins de documentation d'API pris en charge

| Approche | À utiliser lorsque |
| --- | --- |
| Pages générées par OpenAPI | Vous disposez déjà d'une spécification JSON OpenAPI 3.x et souhaitez que dubstack génère les pages de points de terminaison correspondantes. |
| Pages MDX manuelles | Vous souhaitez contrôler entièrement le contenu tout en reliant chaque page à une opération API. |
| Playgrounds intégrés | Vous souhaitez placer un exemple de point de terminaison exécutable dans un guide ou un tutoriel. |
| API d'exécution de la documentation | Vous souhaitez inspecter les points de terminaison publics qui alimentent les fonctionnalités d'IA et le playground d'un site publié. |

## Source de vérité

Gardez les spécifications API dans le même dépôt Git que le reste de vos documents.

L'emplacement canonique pour la spécification principale est :

```text
api-reference/openapi.json
```

Vous pouvez également stocker des spécifications nommées sous :

```text
api-reference/openapi/payments.json
api-reference/openapi/admin.json
```

Après la synchronisation du dépôt, dubstack stocke la spécification avec les artefacts publiés et l'utilise pour générer les pages de référence API et les playgrounds.

<Callout type="info">

</Callout>
