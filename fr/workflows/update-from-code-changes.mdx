---

Le flux de mise à jour à partir des modifications de code examine les dépôts sources sélectionnés et rédige des mises à jour de documentation lorsqu'il y a des changements dans le comportement du produit.

Utilisez-le lorsque le code, les schémas d'API, le comportement de la CLI, les options de configuration ou les flux de produit évoluent plus rapidement que les documents ne peuvent être mis à jour manuellement.

## Ce qu'il fait

Lorsqu'il est activé pour un déploiement, le flux est conçu pour :

- lire les modifications sources fusionnées provenant des dépôts sélectionnés
- comparer les modifications sources avec le dépôt de documentation connecté
- identifier le comportement visible par l'utilisateur nécessitant une documentation
- rédiger des mises à jour de documentation ciblées dans le dépôt de documentation
- ouvrir une demande de révision propre au fournisseur à moins que les mises à jour automatiques ne soient explicitement activées
- citer les dépôts sources, les pull requests, les fichiers ou les soumissions lorsqu'ils sont disponibles
- enregistrer l'état de l'exécution, les fichiers modifiés, les sources de contexte et l'utilisation des crédits dans l'historique du flux

Les dépôts sources sélectionnés sont un contexte en lecture seule. Le flux écrit les modifications de documentation générées dans le dépôt de documentation connecté.

## Dépôts sources

Les dépôts sources peuvent être distincts du dépôt de documentation.

| Rôle du dépôt | Comportement |
| --- | --- |
| Dépôt de documentation | Cible d'écriture pour les modifications de documentation générées. |
| Dépôt source | Contexte en lecture seule pour les changements de produit, d'API ou de fonctionnalité. |
| Dépôt de contexte | Contexte supplémentaire en lecture seule utilisé par le flux lorsqu'il est pris en charge. |

Un site de documentation GitHub peut inspecter un dépôt source GitLab ou auto-hébergé lorsqu'une connexion, un webhook et des autorisations sont configurés pour ce déploiement.

## Configuration requise

Avant d'activer l'automatisation des modifications de code :

1. Connectez un dépôt de documentation basé sur Git avec accès en écriture.
2. Ajoutez au moins un dépôt source dans les paramètres Git ou la configuration du flux.
3. Confirmez que la carte du dépôt source est valide.
4. Choisissez un chemin d'accès pour les monorepos lorsqu'une partie seulement du dépôt est pertinente.
5. Confirmez que le profil du modèle d'élaboration est disponible.
6. Commencez en mode **Revue requise**.

## Déclencheurs et mode de mise à jour

| Paramètre | Comportement |
| --- | --- |
| Déclencheur par défaut | Calendrier personnalisé, deux fois par semaine |
| Déclencheur facultatif | Changement de code après un événement de revue fusionné |
| Mode recommandé initial | Revue requise |
| Mode automatique | Utilisez uniquement après des exécutions de revue nettoyées |
| Cible d'écriture | Dépôt de documentation connecté |
| Dépôts de contexte | Pris en charge |

Les exécutions planifiées regroupent les changements fusionnés depuis l'exécution comparable précédente. Les déclencheurs de changement de code sont utiles lorsque les docs doivent être mises à jour plus près du moment où les changements de produit sont fusionnés.

Les poussées directes peuvent toujours être inspectées par les exécutions planifiées, mais les déclencheurs basés sur des événements de revue doivent reposer sur des pull requests fusionnées, des demandes de fusion ou des événements de revue natifs du fournisseur.

## Portée de chemin

La portée de chemin maintient les exécutions monorepo concentrées.

Utilisez la portée de chemin lorsque :

- un seul dépôt contient de nombreux services non liés
- seulement un seul package ou application affecte le site de documentation
- les spécifications d'API générées se trouvent sous un répertoire connu
- les docs doivent ignorer les changements liés uniquement à l'infrastructure

Si les métadonnées des fichiers modifiés sont disponibles, les changements de source en dehors de la portée de chemin doivent être ignorés avant que l'exécution n'utilise les crédits d'auteur.

## Utilisation des crédits

Les exécutions de changement de code sont des exécutions de flux de travail auto-mises à jour et comptent dans l'utilisation des crédits de flux de travail.

L'estimation actuelle de planification est de **180 crédits par exécution**. L'utilisation réelle peut varier selon :

- nombre de changements de source inspectés
- nombre de dépôts sélectionnés
- étendue de la portée de chemin
- quantité de contexte documentaire récupérée
- nombre de fichiers modifiés par la mise à jour générée
- routage du modèle et profil du flux de travail sélectionné

Voir [Crédits et utilisation de l'IA](/fr/ai/credits-usage) pour le modèle d'allocation partagée.

## Liste de vérification

Avant de fusionner les modifications générées, confirmez :

- la modification source est visible pour l'utilisateur
- les documents générés ciblent la bonne page et le bon dépôt
- les exemples de code correspondent au comportement livré
- les mises à jour de la référence API correspondent à la source officielle OpenAPI
- les affirmations générées citent un contexte source suffisant pour les réviseurs
- les modifications non liées au monorepo ont été ignorées
