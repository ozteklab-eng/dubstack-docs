Utilisez un sous-chemin `/docs` lorsque votre site principal est déjà hébergé sur le domaine racine et que vous souhaitez que la documentation apparaisse sous le même nom d'hôte.

```text
example.com          -> your main website
example.com/docs     -> your dubstack documentation site
```

## Comment cela diffère d'un sous-domaine personnalisé

Un sous-domaine personnalisé tel que `docs.example.com` est basé sur l'hôte. Vous pointez le DNS vers dubstack et l'hôte complet sert vos documents.

Un sous-chemin tel que `example.com/docs` est basé sur le chemin. Le DNS ne peut pas pointer qu'un seul chemin vers dubstack. L'application, le worker d'extrémité ou le proxy inverse qui gère `example.com` doit acheminer `/docs` et `/docs/*` vers l'origine dubstack pour ce site.

## Exigences

Pour utiliser un sous-chemin, vous avez besoin de :

- Un site dubstack publié.
- Le contrôle du site principal ou du proxy d'extrémité du domaine.
- Une route qui transfère `/docs` et tous les chemins imbriqués vers l'origine dubstack.
- La capacité à conserver la méthode de requête originale, la chaîne de requête, le corps et les en-têtes de réponse.
- La capacité à transférer `X-Forwarded-Host`, `X-Public-Host` et `X-Forwarded-Proto`.
- La capacité à transférer `X-Docs-Base-Path` et `X-Public-Mcp-Url` lors de l'activation du MCP public.

## Activer l'hébergement sous-chemin

1. Ouvrez votre site dans le tableau de bord dubstack.
2. Allez dans **Paramètres → Déploiement → Domaine personnalisé**.
3. Activez **Héberger à `/docs`**.
4. Entrez votre domaine racine, par exemple `example.com`.
5. Cliquez sur **Ajouter un domaine**.
6. Copiez l'hôte d'origine généré.

L'hôte d'origine a cette forme :

```text
<site>--origin.dubstack.live
```

Les routes de page de proxy vers l'origine avec le chemin `/docs` préservé :

```text
https://example.com/docs     -> https://<site>--origin.dubstack.live/docs
https://example.com/docs/... -> https://<site>--origin.dubstack.live/docs/...
```

Les points de terminaison d'exécution et les fichiers de découverte restent montés à `/docs` pour les visiteurs, mais sont acheminés vers le chemin d'origine canonique :

```text
https://example.com/docs/api/theme           -> https://<site>--origin.dubstack.live/api/theme
https://example.com/docs/feedback            -> https://<site>--origin.dubstack.live/feedback
https://example.com/docs/llms.txt            -> https://<site>--origin.dubstack.live/llms.txt
https://example.com/docs/mcp                 -> https://<site>--origin.dubstack.live/mcp
https://example.com/docs/.well-known/mcp     -> https://<site>--origin.dubstack.live/.well-known/mcp
```

## Modèle de routage

Lorsqu'un site est monté à `/docs`, le site principal continue à servir tout ce qui se trouve en dehors du chemin des documents.

```text
GET /                  -> root website
GET /pricing           -> root website
GET /docs              -> dubstack origin
GET /docs/quickstart   -> dubstack origin
GET /docs/_next/...    -> dubstack origin assets
GET /docs/api/theme    -> dubstack origin API
GET /docs/fonts/...    -> dubstack font assets
GET /docs/llms.txt     -> dubstack origin AI-readable index
GET /docs/skill.md     -> dubstack origin agent skill file
GET /docs/mcp          -> dubstack origin public MCP server
GET /docs/.well-known/* -> dubstack origin discovery metadata
```

Ne supprimez pas `/docs` de l'URL publique vue par les utilisateurs. Votre proxy peut acheminer les chemins d'exécution sélectionnés vers leur chemin d'origine canonique, mais doit conserver l'URL montée publique dans les en-têtes transmis pour que dubstack puisse générer des liens montés, des URLs de source, des appels d'assistant, des réponses de recherche, des métadonnées MCP et des index de LLM.

Pour le MCP public, le point de terminaison client doit rester monté à `/docs/mcp`. Votre proxy doit également transmettre :

```text
X-Docs-Base-Path: /docs
X-Public-Mcp-Url: https://example.com/docs/mcp
```

Ces en-têtes permettent à dubstack de générer des URLs montées publiques et permettent aux cartes de découverte MCP et de serveur d'annoncer l'URL montée publique au lieu de l'hôte `--origin.dubstack.live` brut.

Préservez les en-têtes de cache de réponse dubstack. En particulier, ne mettez pas en cache `/docs/mcp` ; c'est le point de terminaison de transport HTTP Streamable MCP. Les métadonnées de découverte sous `/docs/.well-known/mcp*` peuvent être mises en cache normalement.

## Exemple de Worker Cloudflare

Utilisez-le lorsque votre domaine racine est déjà routé via Cloudflare Workers.

Remplacez `DOCS_ORIGIN_HOST` et `PUBLIC_HOST` par les valeurs affichées dans votre tableau de bord dubstack.

```js
const DOCS_ORIGIN_HOST = '<site>--origin.dubstack.live';
const PUBLIC_HOST = 'example.com';
const DOCS_PREFIX = '/docs';
const REWRITABLE_PREFIXES = [
  '/_next/',
  '/api/',
  '/img/',
  '/assets/',
  '/images/',
  '/fonts/',
  '/favicon',
  '/logo',
  '/site.webmanifest',
  '/apple-touch-icon',
  '/robots.txt',
  '/sitemap.xml',
  '/openapi.json',
  '/api-reference/openapi.json',
  '/feedback',
  '/llms',
  '/skill.md',
  '/.well-known/agent-card.json',
  '/.well-known/agent-skills/',
  '/.well-known/skills/',
];

function shouldPrefix(value) {
  return value.startsWith('/') &&
    value !== DOCS_PREFIX &&
    !value.startsWith(`${DOCS_PREFIX}/`) &&
    REWRITABLE_PREFIXES.some((prefix) => value.startsWith(prefix));
}

function prefixValue(value) {
  return shouldPrefix(value) ? `${DOCS_PREFIX}${value}` : value;
}

function normalizeHostname(value) {
  return String(value || '')
    .trim()
    .toLowerCase()
    .replace(/^https?:\/\//, '')
    .replace(/\/.*$/, '')
    .replace(/:\d+$/, '');
}

function withDocsPrefix(pathname) {
  if (pathname === DOCS_PREFIX || pathname.startsWith(`${DOCS_PREFIX}/`)) return pathname;
  if (pathname === '/') return DOCS_PREFIX;
  return `${DOCS_PREFIX}${pathname.startsWith('/') ? pathname : '/' + pathname}`;
}

function prefixLocationValue(value) {
  const trimmed = String(value || '').trim();
  if (!trimmed || trimmed.startsWith('//')) return value;

  if (/^https?:\/\//i.test(trimmed)) {
    try {
      const url = new URL(trimmed);
      const hostname = normalizeHostname(url.hostname);
      if (hostname !== DOCS_ORIGIN_HOST && hostname !== PUBLIC_HOST) return value;
      url.protocol = 'https:';
      url.hostname = PUBLIC_HOST;
      url.port = '';
      url.pathname = withDocsPrefix(url.pathname);
      return url.toString();
    } catch {
      return value;
    }
  }

  if (!trimmed.startsWith('/')) return value;

  try {
    const url = new URL(trimmed, 'https://docs.local');
    return new URL(`${withDocsPrefix(url.pathname)}${url.search}${url.hash}`, `https://${PUBLIC_HOST}`).toString();
  } catch {
    return new URL(withDocsPrefix(trimmed), `https://${PUBLIC_HOST}`).toString();
  }
}

function isRedirectStatus(status) {
  return status >= 300 && status < 400;
}

function prefixSrcSet(value) {
  return value
    .split(',')
    .map((candidate) => {
      const leading = candidate.match(/^\s*/)?.[0] || '';
      const trimmed = candidate.trim();
      if (!trimmed) return candidate;
      const [url, ...descriptors] = trimmed.split(/\s+/);
      return `${leading}${[prefixValue(url), ...descriptors].join(' ')}`;
    })
    .join(',');
}

function prefixCssUrls(value) {
  return value.replace(/url\((['"]?)(\/[^'")]+)\1\)/g, (match, quote, url) => {
    const next = prefixValue(url);
    return next === url ? match : `url(${quote}${next}${quote})`;
  });
}

class DocsAssetPrefixer {
  element(element) {
    for (const attr of ['href', 'src', 'action', 'poster']) {
      const value = element.getAttribute(attr);
      if (value) element.setAttribute(attr, prefixValue(value));
    }

    const srcset = element.getAttribute('srcset');
    if (srcset) element.setAttribute('srcset', prefixSrcSet(srcset));

    const style = element.getAttribute('style');
    if (style) element.setAttribute('style', prefixCssUrls(style));
  }
}

function prefixResponseHeaders(response) {
  const headers = new Headers(response.headers);

  const link = headers.get('link');
  if (link) {
    headers.set('link', link.replace(/<([^>]+)>/g, (match, href) => (
      shouldPrefix(href) ? `<${DOCS_PREFIX}${href}>` : match
    )));
  }

  const location = headers.get('location');
  if (location) {
    headers.set('location', prefixLocationValue(location));
  }

  headers.delete('content-length');
  return cloneResponseWithHeaders(response, headers);
}

function cloneResponseWithHeaders(response, headers) {
  return new Response(isRedirectStatus(response.status) ? null : response.body, {
    status: response.status,
    statusText: response.statusText,
    headers,
  });
}

function shouldProxy(pathname) {
  return pathname === DOCS_PREFIX || pathname.startsWith(`${DOCS_PREFIX}/`);
}

function stripDocsPrefix(pathname) {
  if (pathname === DOCS_PREFIX) return '/';
  if (pathname.startsWith(`${DOCS_PREFIX}/`)) {
    return pathname.slice(DOCS_PREFIX.length) || '/';
  }
  return null;
}

function mapMountedPathToOrigin(pathname) {
  const stripped = stripDocsPrefix(pathname);
  if (stripped === '/mcp' || stripped === '/mcp/') return '/mcp';
  if (stripped === '/.well-known/mcp' || stripped === '/.well-known/mcp.json') return stripped;
  if (stripped?.startsWith('/.well-known/mcp/')) return stripped.replace(/\/+$/, '');
  if (stripped === '/.well-known/agent-card.json') return stripped;
  if (stripped?.startsWith('/.well-known/agent-skills/') || stripped?.startsWith('/.well-known/skills/')) {
    return stripped.replace(/\/+$/, '');
  }
  if (stripped && REWRITABLE_PREFIXES.some((prefix) => stripped.startsWith(prefix))) return stripped;
  return pathname;
}

function buildProxyRequest(request) {
  const target = new URL(request.url);
  target.hostname = DOCS_ORIGIN_HOST;
  target.protocol = 'https:';
  target.pathname = mapMountedPathToOrigin(target.pathname);

  const proxyRequest = new Request(target, request);
  proxyRequest.headers.set('X-Forwarded-Host', PUBLIC_HOST);
  proxyRequest.headers.set('X-Public-Host', PUBLIC_HOST);
  proxyRequest.headers.set('X-Forwarded-Proto', 'https');
  proxyRequest.headers.set('X-Docs-Base-Path', DOCS_PREFIX);
  proxyRequest.headers.set('X-Public-Mcp-Url', `https://${PUBLIC_HOST}${DOCS_PREFIX}/mcp`);
  return new Request(proxyRequest, { redirect: 'manual' });
}

export default {
  async fetch(request) {
    const url = new URL(request.url);

    if (!shouldProxy(url.pathname)) {
      return fetch(request);
    }

    const response = prefixResponseHeaders(await fetch(buildProxyRequest(request)));
    if (isRedirectStatus(response.status)) return response;

    const contentType = response.headers.get('content-type') || '';

    if (contentType.includes('text/css')) {
      const css = await response.text();
      return new Response(prefixCssUrls(css), {
        status: response.status,
        statusText: response.statusText,
        headers: response.headers,
      });
    }

    if (!contentType.includes('text/html')) return response;

    return new HTMLRewriter()
      .on('[href],[src],[action],[poster],[srcset],[style]', new DocsAssetPrefixer())
      .transform(response);
  }
};
```

Limitez ces réécritures au trafic `/docs`. Le tableau de bord dubstack génère une copie spécifique au site de ce fragment Worker avec votre hostname d'origine réel et votre hôte public remplis.

## Exemple de proxy inverse générique

Pour les proxies inverses de type Nginx, préservez `/docs` pour les routes de page et redirigez les points de terminaison de runtime vers leurs chemins d'origine canoniques.

```nginx
location = /docs/mcp {
  proxy_pass https://<site>--origin.dubstack.live/mcp;
  proxy_set_header X-Forwarded-Host $host;
  proxy_set_header X-Public-Host $host;
  proxy_set_header X-Forwarded-Proto https;
  proxy_set_header X-Docs-Base-Path /docs;
  proxy_set_header X-Public-Mcp-Url https://$host/docs/mcp;
}

location /docs/.well-known/ {
  rewrite ^/docs(/.*)$ $1 break;
  proxy_pass https://<site>--origin.dubstack.live;

  proxy_set_header X-Forwarded-Proto https;
```

## Validation

Après la configuration de la route, vérifiez :

- `/docs` charge la page d'accueil des documents.
- `/docs/quickstart` ou une autre page imbriquée s'affiche directement après une actualisation.
- Les outils de développement du navigateur montrent que les ressources statiques sont chargées depuis `/docs/_next/...`, et non depuis `/_next/...`.
- `/docs/api/theme` renvoie les données du thème du site.
- `/docs/llms.txt` liste les URL des documents sous `/docs`.
- `/docs/skill.md` renvoie du Markdown.
- `/docs/feedback` renvoie la réponse du point de terminaison de feedback et n'est pas mise en cache.
- `/docs/mcp` renvoie la réponse du transport MCP public et n'est pas mise en cache.
- `/docs/.well-known/mcp` renvoie un document de découverte dont `url` est `https://example.com/docs/mcp`.
- `/docs/.well-known/mcp/server-card.json` liste les outils MCP publics.
- `/docs/.well-known/agent-skills/index.json` renvoie le manifeste des compétences de l'agent.
- `/docs/.well-known/agent-card.json` renvoie la carte de l'agent.
- La recherche, l'assistant, le playground d'API et la navigation entre les pages fonctionnent à partir du chemin monté.
- Les liens à l'intérieur des documents maintiennent les utilisateurs sous `/docs`.

## Dépannage

### La page d'accueil des documents fonctionne, mais les pages imbriquées renvoient 404

Votre proxy gère probablement `/docs` mais pas `/docs/*`. Ajoutez la route avec le caractère joker.

### Les ressources statiques sont chargées depuis le domaine racine

Assurez-vous que votre proxy préserve le préfixe `/docs` et transmette les en-têtes de réponse générés. Si votre application racine réécrit le HTML, elle ne doit pas supprimer `/docs` des URLs des ressources dubstack.

### Le site affiche l'URL d'origine brute

Transmettez `X-Forwarded-Host`, `X-Public-Host` et `X-Forwarded-Proto`. Ces en-têtes indiquent à dubstack quel domaine public sert les documents montés.

### L'hôte d'origine apparaît dans les résultats de recherche

Ne reliez pas les utilisateurs à `https://<site>--origin.dubstack.live`. Ce nom d'hôte est réservé au trafic de proxy uniquement. Les réponses d'origine directe sont marquées `noindex`, mais vos liens publics et votre carte du site doivent utiliser votre domaine monté.

### Claude ou un autre client MCP se connecte mais n'affiche aucun outil

Vérifiez `/docs/.well-known/mcp/server-card.json` et confirmez que le champ `url` pointe vers `https://example.com/docs/mcp`, et non vers le nom d'hôte `--origin`. Si cela pointe vers l'origine, transférez `X-Public-Mcp-Url` depuis le proxy et effacez le cache CDN pour `/docs/.well-known/mcp*`.

Si le connecteur s'ajoute correctement mais n'affiche aucun outil ou que les appels d'outils échouent, vérifiez également que le proxy transfère `X-Docs-Base-Path: /docs` et ne met pas en cache `/docs/mcp`.

## Quand utiliser un sous-domaine au lieu d'un domaine

Utilisez un domaine personnalisé basé sur l'hôte tel que `docs.example.com` lorsque vous souhaitez la configuration la plus simple. Un sous-domaine n'a besoin que de la vérification DNS et du domaine.

Utilisez `/docs` lorsque le partage du domaine racine est plus important que la simplicité opérationnelle.
