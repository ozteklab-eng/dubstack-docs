Team members let more people work in the same dubstack organization.

Invite teammates after the site source and first publish are working, then assign the least-privileged role that lets each person do their job.

## Requirements

Team invites depend on plan and role:

| Requirement | Details |
| --- | --- |
| Plan | Team invites are available on Pro and Enterprise workspaces. |
| Inviter role | Editors can invite editors and viewers. Admins can invite admins, editors, and viewers. |
| Invite email | The invited user must accept with the same email address. |

Free workspaces can evaluate the product with the first admin account. Upgrade when you need team collaboration.

## Invite a member

1. Open the dashboard.
2. Go to **Settings > Organization > Members**.
3. Enter the teammate's email address.
4. Choose the role.
5. Send the invite.
6. Ask the teammate to accept from the email address that received the invite.

Pending invites appear on the members page until they are accepted, cancelled, or expired.

## Choose a role

| Role | Use when |
| --- | --- |
| Admin | The person manages members, billing, SSO, domains, Git source, or organization settings. |
| Editor | The person writes, reviews, publishes, or configures docs. |
| Viewer | The person needs read-only dashboard visibility. |

See [Roles](/dashboard/roles) for the full permission matrix.

## Manage pending invites

Use pending invites to confirm who still needs access.

Recommended maintenance:

- cancel invites that were sent to the wrong email address
- resend invites only after confirming the person still needs access
- avoid sending admin invites unless the recipient needs admin-level duties
- review pending invites before changing plan or ownership state

## Git provider access

Dashboard membership and Git provider access are separate.

A teammate may need both:

- dashboard access to use the editor, settings, workflows, and analytics
- repository access to review or merge pull requests
- provider app access if they manage repository installation

If a teammate can edit in dubstack but cannot merge a pull request, update the Git provider permissions or ask a repository maintainer to review the change.

## Offboard a member

Use **Revoke credentials** when you need staged offboarding or compromise response without removing dashboard membership.

This action revokes active Admin API keys created by the member, disconnects their GitLab authoring OAuth connection, and disconnects Forgejo source repositories connected with that member's token. The member stays in the organization with the same role.

Use **Remove** when the person should no longer access the dashboard.

When removing a teammate:

1. Remove dashboard membership.
2. Review pending invites for the same person.
3. Review Git provider repository access.
4. Review Slack, Jira, and other integration access.
5. Rotate shared credentials the person could access.
6. Review recent activity or audit logs if the workspace has audit logging enabled.

Removing a member automatically revokes active Admin API keys created by that member, disconnects their GitLab authoring OAuth connection, and disconnects Forgejo source repositories connected with that member's token.

<Callout type="warning">
  Dashboard removal does not remove the person from GitHub, GitLab, Forgejo, Slack, Jira, or your identity provider. Review those systems separately, especially for shared workspace integrations and repository permissions.
</Callout>
