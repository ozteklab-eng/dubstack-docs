Feedback analytics show how readers and agents rate docs pages, assistant answers, and supported agent actions.

Open **Analytics > Feedback** from the dashboard to review feedback for the selected deployment.

## What is tracked

The feedback view can include:

- total feedback count for the selected date range
- positive and negative rating counts
- daily feedback volume
- sentiment breakdown
- pages where feedback was submitted
- feedback source breakdown
- review status breakdown
- recent feedback entries
- internal review notes
- optional reader email addresses when collection is enabled

Feedback is scoped to the current deployment. Switching deployments changes the analytics scope.

## Feedback panels

| Panel | Use it to |
| --- | --- |
| Feedback over time | See whether feedback volume is increasing or dropping over the selected date range. |
| Sentiment | Compare positive and negative ratings. |
| Top pages | Find pages that receive the most feedback. |
| Sources | Separate page feedback, assistant feedback, and agent feedback. |
| Review status | See how many feedback entries are pending, in progress, resolved, or dismissed. |
| Recent feedback | Review the latest detailed submissions, page paths, sources, optional reader emails, review status, and internal notes. |

## Review statuses

Every feedback entry starts as **Pending**.

Use statuses to keep the feedback queue actionable:

| Status | Meaning |
| --- | --- |
| Pending | Awaiting review. |
| In progress | A docs or product follow-up is underway. |
| Resolved | The issue has been addressed. |
| Dismissed | The feedback is not actionable, duplicate, or no longer relevant. |

Change the status from the selector beside a recent feedback entry. The **Review status** panel updates with the latest counts for the selected date range.

## Internal notes

Use internal notes to track team-only context for a feedback entry.

Examples:

- `Assigned to docs owner`
- `Duplicate of Jira DOC-42`
- `Resolved by PR #128`
- `Dismissed because the page already documents this behavior`

Notes are stored with the feedback event and are only visible to dashboard users with access to the deployment.

## Enable page feedback

Page feedback depends on the **Thumbs rating** add-on.

1. Open **Settings > Deployment > Add-ons**.
2. Enable **Thumbs rating**.
3. Publish or refresh the docs site.
4. Confirm public pages show the feedback control.
5. Review submitted ratings in **Analytics > Feedback**.

If the add-on is disabled, public page feedback submissions are rejected for that deployment.

## Optional reader emails

Page feedback can optionally collect a reader email address.

Enable this from **Settings > Deployment > Add-ons**:

1. Enable **Thumbs rating**.
2. Enable **Collect reader emails**.
3. Add a short email disclaimer.
4. Publish or refresh the docs site.

Reader email collection is optional for the reader. If they submit an address, the feedback form validates it before sending the event. The email then appears in the **Recent feedback** list so your team can follow up.

Reader emails are not collected for page feedback unless the deployment add-on is enabled.

## Feedback sources

| Source | Meaning |
| --- | --- |
| Page feedback | Reader rating submitted from a docs page. |
| Assistant feedback | Rating submitted against an assistant answer. |
| Agent feedback | Structured feedback submitted by an enabled agent surface. |

Not every source is available on every plan or deployment. Use the Add-ons page to see the current capability state.

Agent feedback appears only when the **Agent feedback** add-on is enabled and the submitting surface sends a documentation-quality issue through the public feedback path.

## Use feedback with workflows

Feedback can power documentation improvement workflows when the workflow and required capabilities are available.

For best results:

- collect page paths with feedback
- ask readers for short comments when something is not helpful
- keep negative feedback tied to concrete docs gaps
- review generated pull requests before merging
