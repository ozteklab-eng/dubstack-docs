The setup checklist helps new sites finish the core steps that make the docs workspace useful.

It appears in the top toolbar when there are setup actions available for your role and site. The progress icon fills as each action is completed.

## What the checklist tracks

The checklist is calculated from live dashboard state, not from a static counter.

| Item | Completed when |
| --- | --- |
| Connect GitHub or enable automatic updates | A supported repository is connected and ready for authoring updates. |
| Make an update | A non-initial deployment or content update has run for the current site. |
| Invite a teammate | The organization has more than one member or at least one pending invite. |
| Add custom domain | The current site has a custom domain configured. |
| Create an automation | At least one workflow is configured or enabled for the site. |
| Install Slack app | Slack is eligible for the site and the installation has the required scopes. |

Some items only appear when your role can perform them. For example, repository and custom domain setup require owner or admin access, while editor-level setup items are shown to owners, admins, and editors.

## Visible items and destinations

The checklist only shows actions that are relevant to the current site, role, and deployment capability state.

| Item | Who sees it | Opens |
| --- | --- | --- |
| Connect GitHub or enable automatic updates | Owners and admins | **Settings > Deployment > Git settings** |
| Make an update | Owners, admins, and editors | **Editor** |
| Invite a teammate | Owners, admins, and editors | **Settings > Organization > Members** |
| Add custom domain | Owners and admins | **Settings > Deployment > Custom domain** |
| Create an automation | Owners, admins, and editors | **Automations** |
| Install Slack app | Owners, admins, and editors when Slack is configured and eligible | **Agent** or Slack install flow |

Deployments that are not eligible for repository or Slack authoring can hide those setup items.

## Open a setup item

1. Open the dashboard for the site.
2. Click **Complete your setup** in the top toolbar.
3. Select the setup item you want to finish.
4. Complete the linked flow.
5. Return to the dashboard and refresh if the status has not updated yet.

The checklist links directly to the relevant dashboard area, such as Git settings, the editor, members, custom domain settings, automations, or the agent page.

## Progress behavior

Progress is based on completed items divided by visible checklist items.

If your role cannot complete an item, that item is not included in your visible checklist. If a deployment is not eligible for repository or Slack authoring, those setup items are not included in the progress calculation.

The top toolbar shows the same progress as a small pie indicator. The expanded checklist shows the numeric percentage.

You can hide the checklist from the toolbar. Hiding is stored in your browser for the current organization and site, so hiding it for one site does not hide it for every deployment.

## Troubleshooting

### Progress still shows zero

Check that you are on the intended site, not another site in the same organization. Then open the checklist and follow the linked actions.

If the dashboard was open while you completed a setup action, refresh the page so the checklist refetches repository, deployment, member, Slack, and automation state.

### Repository setup does not complete

Open **Settings > Deployment > Git settings** and confirm the provider, repository owner, repository name, deployment branch, and app installation are present.

GitHub requires the app installation to be available. GitLab requires authoring readiness to be healthy.

### Make an update is not complete

Initial onboarding deployments do not count as a user update. Edit a page, update configuration, merge a content change, or run a manual update after source changes are present.

### Slack does not appear

Slack only appears when the site is eligible for agent Slack setup and the current role can edit the site. Open [Agent integrations](/ai/integrations) if you need to review the agent integration status.
