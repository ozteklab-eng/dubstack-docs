The Usage page shows how AI-powered dubstack surfaces consume workspace credits and retrieval resources.

Use it to understand what is driving AI usage before changing workflows, assistant settings, or billing allowances.

## Open usage settings

Workspace admins can open **Settings > Organization > Usage** from the dashboard.

The page is scoped to the selected site and uses the same workspace identity as the rest of the dashboard. If you manage multiple sites, confirm the current site in the sidebar before comparing usage.

## Summary metrics

The usage summary includes:

| Metric | Meaning |
| --- | --- |
| AI runs | Count of assistant, agent, Slack, and workflow AI runs in the selected period. |
| Credits used | Charged credits when billing is active, with estimated credits as the reporting fallback. |
| AI allowance | Remaining monthly workspace allowance, plus credits used against the monthly limit. |
| Tokens | Input, output, and total tokens reported by the model provider when available. |
| Model cost | Provider cost estimate for internal cost monitoring. |
| Retrieval requests | Retrieval calls made by assistant or agent surfaces. |
| Average latency | Average retrieval latency for the selected period. |

The period selector lets you review the last 7, 30, or 90 days.

<Callout type="info">
  The usage period selector changes the activity rows and charts. The AI allowance card uses the current monthly workspace billing window so you can see remaining credits against the active allowance.
</Callout>

## Breakdowns

Usage can be grouped by:

- product surface
- run type
- provider
- model
- retrieval mode
- retrieval surface

These breakdowns help identify whether usage is coming from public assistant traffic, dashboard agent work, Slack requests, or workflows.

## Activity log

The activity log lists recent AI runs and retrieval calls for the selected period.

Each AI run can show:

- source and run type
- model or provider
- status
- credits
- tokens
- created time

Each retrieval call can show:

- retrieval surface
- resolved retrieval mode
- provider or model
- outcome
- source count
- latency

## Export usage

Use **Export CSV** to download the currently selected period's activity rows.

The export includes the same recent AI runs and retrieval events shown on the page, with columns for record type, scope, timestamp, source or surface, run type or retrieval mode, provider, model, status, credits, tokens, sources, and latency.

Exports are generated in the browser from the data already loaded for your current site and period. Change the period selector before exporting if you need a 7-day, 30-day, or 90-day view.

## Usage and billing

Credits are reporting and billing units, not raw tokens. Token count, model route, retrieval work, and workflow complexity can all contribute to a credit estimate.

The AI allowance summary shows whether quota enforcement is currently passive or enforced for the workspace:

- **Passive** means usage is tracked and reported, but requests are not blocked by the allowance.
- **Enforced** means eligible AI requests are checked against the workspace allowance before the run starts.

The Credit policy section shows the current plan state, included monthly allowance, package options, overage mode, alert thresholds, and rollover behavior.

Plan behavior is:

- Free workspaces have no permanent included AI credits unless a trial or entitlement is active.
- Pro trials can use the Pro allowance during the trial window.
- Pro workspaces include a default 10,000 AI credits per month.
- Enterprise workspaces can have custom allowances, routing, and operational controls.

Overage is opt-in. If overage is disabled and quota enforcement is active, eligible AI requests can be blocked once the enforced allowance is exhausted.

If usage looks higher than expected:

1. Check which product surface is consuming the most credits.
2. Review workflow schedules and scopes.
3. Check whether broad repository or integration context is being pulled unnecessarily.
4. Adjust assistant or workflow settings before changing the billing plan.
