Feedback shows where readers and agents struggle with your documentation.

Enable feedback from deployment add-ons, then review ratings and comments from the dashboard analytics view.

<Info>
  Feedback is deployment-scoped. Enable the add-on for each deployment that should collect ratings.
</Info>

## Feedback types

| Type | What it collects | Where it appears |
| --- | --- | --- |
| Page feedback | Yes/No ratings and optional written comments from docs pages. | **Analytics > Feedback** |
| Assistant feedback | Ratings submitted against assistant answers when assistant feedback is enabled. | **Analytics > Feedback** |
| Agent feedback | Structured content-quality feedback from supported agent surfaces. | **Analytics > Feedback** and public feedback API records |

## Enable page feedback

Page feedback is controlled per deployment.

1. Open **Settings > Deployment > Add-ons**.
2. Enable **Thumbs rating**.
3. Publish or refresh the docs site.
4. Open a public docs page and confirm the **Yes** and **No** feedback controls appear.

Readers can then submit simple page-level ratings from the docs site. Negative ratings can include an optional written comment.

## Collect reader emails

Reader email collection is optional.

1. Open **Settings > Deployment > Add-ons**.
2. Enable **Collect reader emails**.
3. Add a short disclaimer explaining how your team uses submitted email addresses.
4. Save and republish.

When enabled, readers can include an email address with feedback so your team can follow up. Do not request sensitive information in the disclaimer or feedback prompt.

## Enable agent feedback

Agent feedback lets supported AI surfaces submit structured feedback about pages they read. It is intended for documentation-quality issues, such as stale instructions, missing setup steps, or unclear API descriptions.

1. Open **Settings > Deployment > Add-ons**.
2. Enable **Agent feedback**.
3. Keep the public MCP and AI-readable routes available for the deployment.

When enabled:

- the public MCP server advertises the `submit_feedback` tool
- generated AI discovery files include feedback instructions
- Markdown exports can include agent instructions for the current page
- accepted feedback is stored with the selected deployment's analytics

Agents should not use this channel for normal reader questions or support conversations.

Agent feedback must reference a published page that is available through the public MCP server. If a page is hidden from MCP by `searchable: false`, `noindex: true`, or site-wide indexing settings, agent feedback for that path is rejected.

## Review feedback

Open **Analytics > Feedback** from the dashboard.

The feedback view shows:

- feedback over time for the selected date range
- sentiment breakdown for positive and negative ratings
- top pages with submitted feedback
- source breakdown across pages, assistant answers, and agent actions
- review status counts for collected feedback
- recent feedback entries with page path and source metadata
- optional reader email addresses when collection is enabled

Feedback is scoped to the selected deployment. Switch deployments to review a different docs site.

## Manage feedback status

Use review status to track feedback from triage through completion.

| Status | Use it when |
| --- | --- |
| Pending | The feedback is new and has not been reviewed yet. |
| In progress | Someone is actively updating docs or investigating the report. |
| Resolved | The docs change is complete or the reported issue is fixed. |
| Dismissed | The feedback is duplicate, no longer relevant, or not actionable. |

Open **Analytics > Feedback**, then use the status selector beside a recent feedback entry. Status changes are saved for the selected deployment and appear in the **Review status** panel.

## Add internal notes

Internal notes help your team track follow-up without exposing details to readers.

Use notes to:

- assign ownership
- link support tickets or engineering issues
- record why feedback was dismissed
- summarize the docs change that resolved the report

Internal notes are only visible inside the dashboard.

## Turn feedback into fixes

Use feedback as input to content maintenance workflows.

- Group repeated negative feedback by page.
- Add missing steps or examples directly in the affected MDX file.
- Update OpenAPI descriptions when API endpoint feedback is unclear.
- Use workflows to draft targeted improvements when workflow prerequisites are configured.
- Review generated pull requests before merging.
