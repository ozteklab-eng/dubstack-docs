title: Prompts

Use `Prompt` to publish reusable AI prompts inside your docs.

Prompt blocks are useful when a page includes a recommended instruction for an editor, coding assistant, support workflow, or documentation review.

## Basic prompt

```mdx
<Prompt description="Improve this documentation page.">
  You are a technical writing assistant.

  Review this page for clarity, missing prerequisites, and confusing steps.
  Return a short list of improvements.
</Prompt>
```

## Add Cursor

Set `actions` when the prompt should include more than the default copy action.

```mdx
<Prompt
  description="Generate **clear**, concise release notes."
  icon="paperclip"
  actions={["copy", "cursor"]}
>
  Turn the following product changes into release notes.

  Use short headings, group related changes, and flag anything that needs a migration note.
</Prompt>
```

## Props

| Prop | Type | Required | Description |
| --- | --- | --- | --- |
| `description` | `string` | Yes | Heading shown on the prompt card. Supports inline Markdown formatting. |
| `children` | `string` | Yes | Prompt text copied to the clipboard or opened in Cursor. |
| `actions` | `array` | No | Defaults to `["copy"]`. Valid values are `"copy"` and `"cursor"`. |
| `icon` | `string` | No | Icon name shown beside the prompt description. |
| `iconType` | `string` | No | Optional icon variant when supported by the active icon library. |

## Authoring notes

- Keep prompts short enough to review before copying.
- Use placeholders instead of private data.
- Use `actions={["copy", "cursor"]}` when readers should open the prompt directly in Cursor.
- Do not put credentials, magic links, access tokens, or private customer data inside reusable prompts.
